# N1.5 acceptance criteria

**MCP-01** Settings come from `CLICKHOUSE_MCP_KEY_ID`, `CLICKHOUSE_MCP_KEY_SECRET` and `CLICKHOUSE_SERVICE_ID` (missing ones are named; the secret never appears in `repr`), with an optional `CLICKHOUSE_MCP_URL` that must be `https` (plain `http` only for `localhost` or `127.0.0.1`), else a config error naming it. The connection authenticates with `Authorization: Basic base64(id:secret)` over Streamable HTTP (default `https://mcp.clickhouse.cloud/mcp`, SSE event limit set explicitly to 8 MiB instead of the SDK's 1 MiB) and reads the server's tool listing once at open, following `next_cursor` for at most 20 pages and stopping at a repeated cursor. The default read timeout is 30 s. On exit it closes the session and the HTTP client it created; if opening or listing fails, everything opened so far is closed and the error is re-raised. `reopen()` replaces the session (a no-op if another caller already reopened since the generation it saw); `ensure_open()` reopens only when `needs_reopen` is set or the session is not open, and it, `reopen()` and exit must run in the task that opened the connection (A2.1's loop, between turns).
**MCP-02** The model is offered exactly `list_databases`, `list_tables` and `run_select_query`; `serviceId` is absent from their schemas and required lists; `database` is an enum of the pack's databases; the toolbox injects its own `serviceId` and ignores one the model sends; only properties of the model-facing schema are forwarded (other keys are dropped); any other tool and any other database are refused without a server call. The client does not parse SQL: what a query can read is limited by the read-only role (N1.2), not here.
**MCP-03** A query result goes back as JSON `{columns, rows, rows_total, truncated}` with at most `row_cap` (50) rows and at most 12,000 characters: the output is always valid JSON. If longer, column names are cut to 500 characters, and if the names alone still do not fit only the leading names that fit are kept, followed by a `...[n more columns cut]` entry, with no rows; otherwise string or nested cells are cut with a marker, halving the cell limit from 500 down to 16 characters until every row fits, and then trailing rows are dropped to the most that fit; `truncated` is true whenever anything was cut and `rows_total` stays the exact total. Structured content is shaped first, text as the fallback. Shapes read: `{columns, rows}` (rows as lists of the columns' width or objects mapped by column name), ClickHouse JSON `{meta, data}` and lists of objects (union of keys in first-seen order), optionally wrapped in `data`/`result`/`rows` up to 4 levels; only an explicit server-side cut (an integer `rows` above the rows sent, or `truncated: true`) sets `rows_total` to the server's count and `truncated` true; ClickHouse's `rows_before_limit_at_least` is ignored (it counts rows before the query's own LIMIT), so otherwise `rows_total` is the number of rows returned. Rows of the wrong width make the shape unknown. Any other JSON value, non-JSON text or nesting too deep is an unknown shape: `shape_rows` returns `(None, None)` without raising and the raw text goes to the model; non-query results and unknown shapes longer than 12,000 characters are clipped with a note, and tool-error text is cut to 12,000 characters.
**MCP-04** Every call attempt counts, refused ones included; the call after the sixth is refused with a message telling the model to call `final_answer`, and never reaches the server.
**MCP-05** Server-side tool errors come back as tool errors the model can read, never exceptions. SDK `MCPError`s for a closed connection (-32000) and HTTP 5xx/429 or internal errors (-32603) are retried, up to six attempts and within a 45 s wall-clock budget per call (injectable clock): no attempt starts after the budget is spent, each attempt's read timeout and each backoff sleep are capped by the time left. Timeouts (-32001 or `TimeoutError`) are not retried: one attempt, and the message tells the model the query timed out and to simplify it. Protocol errors (parse, invalid request, method not found, invalid params, any other code) are not retried. A toolbox never reopens the connection: when a call ends on connection-closed it sets `needs_reopen`. Calls on one toolbox are serialized by a lock, so concurrent calls are safe. The model-facing error names the kind ("MCP server timeout", "MCP connection closed", ...), its code and the attempts made, never the exception's message, and the API key secret and Basic token, raw and JSON-escaped, are redacted from text and structured content before any slicing or cell cutting, so a cut cannot leave a secret prefix, and from the log. A server that lacks one of the three tools is a config error.
**MCP-06** An in-process fake server shaped like the published tool table (with `serviceId`, a control-plane tool and a slow-query trigger) backs the unit tests through the real MCP protocol, both in-process and over Streamable HTTP served from its ASGI app.
