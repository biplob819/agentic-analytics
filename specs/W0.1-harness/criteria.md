# W0.1 acceptance criteria

**HAR-01** `uv sync` installs the project; `agentic-analytics --version` and `aa --version` print `agentic-analytics 0.0.1`; `pyproject.toml` declares distribution `agentic-analytics`, scripts `agentic-analytics` and `aa` = `agentic_analytics.cli:main`, licence MIT and `requires-python >=3.11`; ruff and ruff-format pre-commit hooks are configured.
**HAR-02** `.github/workflows/ci.yml` runs on push to main and on pull requests with `contents: read` only; it runs ruff check, ruff format check, pyright, pytest excluding `live`, the secret scan, graph eligibility and `uv build`, on Python 3.11 and 3.12 on ubuntu-latest and macos-latest; no workflow (`.yml` or `.yaml`) references secrets, grants write permissions or `id-token`, or publishes a package until B3.3 adds the release workflow.
**HAR-03** The six harness scripts run against this repo; `verify_graph_eligibility.py`, `node_start.py`, `node_converge.py` and `secret_scan.py` each pass `--self-test`, which proves every gate can fail; node ids from every wave letter in Tech Spec §12.2 parse; gate 8 is `gold`; gates 7 to 9 exclude `live` tests.
**HAR-04** `graph.md` holds the 23 nodes of Tech Spec §12.2 with their dependencies and `catalog.tsv` the 133 capabilities of §12.4 with their nodes and notes, both checked against the spec text; `decisions.md` holds D-1 to D-31 with unique ids; `lessons.md` and `changelog.md` exist; `status.py` prints every node and is deterministic.
**HAR-05** The Makefile targets `load`, `gold`, `smoke`, `run` and `report` each call an `agentic-analytics` subcommand that the CLI knows; a subcommand whose node is not green exits 2 and names that node (with `--json` before or after the subcommand, as a JSON object); unknown top-level arguments are an error.
**HAR-06** `evalkit-harness` is pinned to a full 40-character commit SHA; the contract test imports `sql_match`, `ResultSet`, `Interval`, `Resamples`, `interval`, `paired`, `holm`, `percentile_ms`, `Guard`, `GuardRefused`, `PostgresSpend` and `SqliteSpend` and checks `sql_match` on extra columns and tolerance.
**HAR-07** Every non-comment line of `.env.example` is `NAME=` with no value, names are unique and exactly those in Tech Spec §4; git actually ignores `.env`, `.env.*` (not `.env.example`), private keys and the root `data/`; the secret scan detects Langfuse secret keys and any `scheme://user:password@` URL whatever the scheme or case, ignores placeholders and `${VAR}` references, and the live repo scans clean.
