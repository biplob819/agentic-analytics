# B3.1 acceptance criteria

**DSH-01** `render_report(summary, records, out_dir)` writes `index.html` and `summary.vl.json` atomically (mode 0644, no temp files left) and returns the HTML path; the HTML is self-contained, judged on its markup and CSS rather than raw substrings (escaped text such as an agent's SQL may legitimately read `url('https://…')`): parsed with an HTML parser, it has exactly one inline `<script>` and no `src`, no resource-loading tag (`link`, `img`, `iframe`, `object`, `embed`, media, `use`, `base`, `form`, …), no resource-loading or `style` attribute, no protocol-relative or `http(s)` URL in any attribute except a plain `<a href>`, no `javascript:` link, and no `@import` or `url(` inside `<style>`; a planted-markup test proves the checker catches each of these; `summary.vl.json` holds valid Vega-Lite v5 specs for the category, uplift and cost charts built from the same numbers (`separated`, deltas and p-values copied from the summary, not re-derived), plus top-level `synthetic` and `description`; rendering the same inputs twice (into two folders) gives byte-identical files, and a different summary changes them; the bundled synthetic example renders with no keys or network and is labelled synthetic everywhere: the page banner and `<title>`, every chart title (`SYNTHETIC EXAMPLE · …`), `summary.vl.json` (`"synthetic": true` and each spec's description), and fictional model names (`example-agent-a`, `example-agent-b`, `example-cortex`) so no real model name sits next to made-up accuracy; a renamed copy of the example rendered with `example=False` is still labelled on every one of those surfaces through `render_report`, `render_html` and `vega_lite_specs`, `looks_synthetic` catches each giveaway alone (run id, the full fingerprint, an `example-` snapshot, placeholder hashes only when asked) and leaves a real-looking run unstamped; the written files pass `scripts/secret_scan.py` even when records carry key-shaped strings (planted Anthropic, OpenAI and AWS keys and a DSN password are scrubbed, and the same scan catches them unscrubbed).
**DSH-02** Accuracy by category × backend is a table with one row per category in the fixed order plus an overall row and one column per baseline backend; each cell prints the point estimate and 95% interval to one decimal (`62.5%`, `51.2–73.0%`) and `n = …`, with the heat band (five equal bins of the point, h0 below 20% … h4 from 80%, boundaries tested) only as a secondary cue; a category a backend did not run shows a dash with words; each backend gets a dot-and-whisker SVG over categories with one shape per fix set, a legend naming each shape, per-mark `<title>` text, and a data table; every point and whisker end sits at its value on the chart's own (evenly spaced) axis; the caption states that per-category figures are a map, not a ranking (H11).
**DSH-03** The uplift chart plots each (backend, fix) delta in points with its 95% interval and a zero line, and the axis always includes zero (tested with all-positive and all-negative deltas), with marks, whiskers and the zero line at their values on that axis; separated positive deltas are ▲ "above noise, helps", separated negative deltas are ▼ "above noise, hurts" (a harmful fix is shown as separated, not hidden), others are ○ "within noise"; the verdict is written in words beside the mark and in a table with the signed delta, interval and p-value (`<0.001` below 0.001); a run with no uplifts says so.
**DSH-04** A panel shows, per configuration, cost per correct (a dash and "nothing correct" when None), the clarification rate on ambiguous questions next to the false-clarification rate on answer-expected questions with intervals, and latency p50/p95 (OWNER D-62: the Cortex row's latency, and every other Cortex latency figure on the page, carries the note that the Snowflake account is in Thailand and Cortex inference crosses to the US, and that the figure is SQL execution only; no other row carries it), plus total cost and credits by engine; a cost-per-correct bar chart (bars proportional to the summary's values, labelled with them) and a clarification chart carry value labels (bar labels end in "(est.)" while cost is pending and not once reconciled); when `cost_status == "estimated"` a "Cost pending" banner says figures exclude unreconciled warehouse credits and every cost figure is marked estimated; a reconciled summary shows no banner.
**DSH-05** The failure explorer lists every incorrect benchmark record (probes excluded) in a deterministic order (backend, fix set, question, trial) as keyboard-operable `<details>`, filterable by backend and configuration; each shows the question id and text (or "text not provided"), backend and configuration, the agent's SQL, the gold SQL for the backend's engine and a line diff when a gold mapping is given, the mismatch reason (derived from errors or clarification when the scorer left none), the answer text with its line breaks kept and Markdown shown as text, Cortex's reading, what A2.3's chart builder made of the executed rows (tested on the recorded live shapes: a five-town bar, a one-row `year, count` with no chart, a Cortex KPI, a top-25-of-40 bar), the steps, a relative link to the exported trace and a Langfuse link when present; hostile strings (`</script><img src=x onerror=alert(1)>`) in the run id, question text, SQL, answer, reason, model snapshot, attribution or trace fields are escaped everywhere, `javascript:` URLs and unsafe trace paths are never linked, and with no records the section says so.
**DSH-06** The page stamps the licence attribution from the pack (bundled pack resolved by `summary.pack`, explicit pack or string; a warning when none is found), the pack ref, the short snapshot sha (full in a tooltip), as-of date, gold check id, run id and timings, and the gold mode (`single-engine gold` stamped prominently on single-engine runs, D-29); a "SYNTHETIC EXAMPLE" banner appears only when rendering the example; probe verdicts and every status use text and symbols (✓ PASS, ✗ FAIL) as well as colour; the page has light and dark colour schemes, a skip link, a section nav and visible focus styles.
