# R3.1 — Runner, CLI and smoke run

**Wave 3. Depends on:** A2.3, S2.1, M2.1, Q2.2 (gold check: the file format is defined here; Q2.2 writes it). Also uses N1.2 (executors, guard), N1.3 (packs, parity and snapshot records), N1.5, N1.6, A2.1, A2.2, Q2.1, B3.1. **Unblocks:** R3.2, D4.1.

## Goal
Wire every committed module into `agentic-analytics run / smoke / report / reconcile / gold / pack check / init`, with a content-addressed cache that makes resume and rescoring free, a single writer, every record stamped, the run preconditions of US9, the §9 estimate and cost cap, and a golden run that pins `summary.json` byte for byte. No accounts exist yet, so everything is built and proven against the committed fakes.

## Outputs
- `agentic_analytics.run`:
  - `cache.py`: `KeyParts`, `cache_key`, `AskResult`, `AnswerCache` (`.cache/<k[:2]>/<k>.json`, atomic writes).
  - `gold.py`: `GoldCheck` (the `gold/gold_check.json` format), `compute_gold_check_id`, `require_gold`, `current_snapshot`, `require_parity`, `PreconditionError`.
  - `config.py`: `parse_backends`, `parse_fixes`, `fixsets`, `with_overrides`, measured cost assumptions (`measure_assumptions`, `save_assumptions`, `load_assumptions`), `init` templates (`RUN_YAML`, `ENV_EXAMPLE`, `write_init`).
  - `runner.py`: `run_benchmark(cfg, pack, *, services, options) -> RunOutcome`, `Services`, `RunOptions`, `plan_jobs`, `Writer`, `smoke_questions`, `reconcile_run`, `allocate_credits`, `resolve_run`, `load_run`, `services_from_env`, `configured_engines`, `mcp_toolbox_source`.
- `cli.py`: `init`, `pack check`, `gold`, `run`, `smoke`, `report`, `reconcile` built (plus N1.2's `doctor`); `load` and `demo-cache` still name their nodes.
- `tests/run/` (world, cache, gold, runner, CLI) and `tests/golden/` (inputs, recording, stored summary, `record.py`, the `golden` test).

## Decisions
- **Cache key (D-1).** sha256 over canonical JSON of node `ask`, `CODE_VERSION` (`ask-v2`), backend, model snapshot (the configured model id; `cortex_analyst` for Cortex), model parameters (`effort` for the agents; the semantic view name for Cortex), the question's ask hash (id and text only: tolerance, gold SQL, interpretations, author and review status change scoring, not answers; `Record.question_hash` still covers the whole question), the fix set and its content hash, prompt hash, semantic hash (N1.4's `semantic_hash`, for fix runs and Cortex only: an MCP baseline never sees the semantic model), snapshot sha256, trial, as-of date and the loop limits (calls, turns, row caps, wall clock). The cached value is Ask plus Execute: the assembled answer (chart included), the execution of its final SQL, cost, tokens, Cortex messages, warehouse time, model turns and the frozen `fix_hash` in force. Scores are never cached, so `--rescore` is exact and free. Transport failures and timeouts (answer or execution) are never cached, so a resume retries them.
- **Prompt hash offline.** The agents' `prompt_hash` is computed with no MCP tool specs (`prompt_hash(as_of, ())`: version, system prompt, `final_answer` spec and loop texts). The server's tool descriptions are only known after connecting, and the key must be computable for resume and rescore with no connection. Cortex's prompt hash covers its as-of line and a version.
- **Fixes (F3.1, D-13, D-48, D-52).** Every run, baselines included, refuses (exit 1) unless `fixes/FROZEN.json` exists and `frozen_problems(pack)` is empty. Prompt blocks (`descriptions`, `examples`) and the self-check rules text come from `fixes.fix_blocks(pack)`; the self-check hook is `make_self_check(<ClickHouse executor>, load_rules(pack))`, passed to `ask_mcp(self_check=...)`. A record carries the frozen `fix_hash` in force when its answer was made (cached answers keep theirs); `run.json` carries the current one and the freeze's reason. A fix run whose frozen `fix_hash` differs from the one on its cached baseline answers refuses (exit 1) unless `--force-fix-hash REASON` is given; the reason goes to run.log and run.json. Each fix runs alone against the same baseline (§7); the `all` combination is not run.
- **Gold check file** (`<pack>/gold/gold_check.json`, documented in `run/gold.py`): kind, pack ref, snapshot, engines, mode (`cross_engine` / `single_engine`), status, the selected question ids, failures, checked_at and `gold_check_id`. `gold_check_id` = sha256 over canonical JSON of the snapshot, the selected questions' JSON and every gold result's id, engine, sql hash, columns and rows. The runner recomputes it from disk, so editing a question or a gold file after the check refuses the run.
- **Preconditions (RUN-04).** Current snapshot = the newest `snapshot-*.json` in the measurements folder (N1.3). A passing `parity-*.json` for that snapshot must cover the configured engines (`single_engine` status only when one engine is configured). The gold check must pass, name that pack and snapshot, cover the configured engines and match its id. Any failure: exit 1, nothing called, no run folder. Q2.2's `run_gold_check` writes this format.
- **Dry run (OSS-03).** `run --dry-run` needs no engine or model variables and no records: failed preconditions are reported as "a real run would refuse", questions come from the gold-check selection or else the pack quotas (first ids per category), and the estimate prints with no calls, exit 0.
- **Single-engine mode (D-29).** Configured engines come from the §4 variables (`configured_engines`, using N1.2's `executors_from_env`). `--backend all` keeps the backends whose engine is configured; naming a backend whose engine is missing is exit 2. `gold_mode` is `single_engine` when one engine is configured or the gold check covered one; the dashboard prints the stamp.
- **Concurrency.** One worker pool per backend, `concurrency[backend]` workers (defaults 4, 4, 2). Each MCP worker opens its own MCP connection in its own task (N1.5's ownership rule) and builds a fresh `Toolbox` per question; the agents' `run_select_query` goes through `check_sql(..., "clickhouse")` first (D-37).
- **Cost.** The estimate is per ask from `estimate_run` (with the smoke run's measured assumptions when present), printed before the first call. `max_cost_usd` caps **model spend** (D-44) **per invocation**: a resumed run gets the cap afresh, and the outcome prints both this invocation's spend and the model spend behind all of the run's answers (cached ones included). Cortex messages and warehouse time come from trial credits and are reported, not capped. A remaining estimate over the cap stops before any call (exit 3). During the run each ask reserves its estimate on N1.6's `SpendCap` and settles its actual cost; a refused reservation stops new work, in-flight asks finish and are cached, and the run exits 3 with a resume hint. The smoke run defaults to a $2 cap.
- **Writer and records.** One writer task appends `records.jsonl` and `run.log` (JSON lines: event, node, key, cache_hit, job, latency, cost, error); every log line and every CLI message passes A2.3's `Redactor`. Records are stamped with git sha, prompt/fix/semantic hashes, `gold_check_id`, snapshot sha and the run seed. The code version is that of the package's own checkout, not the current folder: `run.json["code"]` holds the sha, a dirty flag (uncommitted changes to tracked files) and the package version, which is the label outside a git checkout (`Record.git_sha` is then `0000000`). Anything that fails after the run folder exists still writes `finished_at`, the error and the exit code into run.json, closes the writer and appends the ledger line (exit 2). Cortex records carry `cost_usd = 0` and `cortex_messages`; `warehouse_elapsed_ms` is the final SQL's execution time. Cortex's own execution of its SQL is reused as the scoring execution (same executor code, D-3).
- **Run folder.** `results/<run_id>/`: `run.json` (manifest: config, hashes, gold mode, engines, timings, exit code), `questions.jsonl`, `records.jsonl`, `run.log`, `summary.json`, `index.html`, `summary.vl.json`, `traces/`. `results/latest` is a text file holding the latest run id (no symlinks). A run folder is never overwritten.
- **Write probes.** When uncached write probes run, every pack table's row count is read through the read-only executors before and after; a change, or a count that cannot be read, is exit 1. A failed probe (M2.1 `probes_failed`) is exit 1.
- **Traces.** Failures (incorrect answers, failed probes) and a deterministic 1-in-10 sample are exported with A2.3's `export_trace`; a configured Langfuse tracer gets every newly called answer.
- **Reconcile (stub of BAS-03).** The operator supplies a JSON file of metered credits per engine; each engine's credits are split over its records in proportion to `warehouse_elapsed_ms` (evenly if none), records and summary are rewritten, and `cost_status` becomes `reconciled`.
- **Smoke.** The first two questions per category (by id) of the gold-check selection, every configured backend, one trial, no probes, $2 cap; the measured turns and tokens per MCP backend are written to `<measurements>/cost-assumptions.json`, which later estimates use.
- **Golden run.** 12 questions (two per category, frozen from the bundled bank, including the ordered top-N q-071 and the unordered q-061), two probes, three backends, three trials, the `examples` fix on both agents (uplift and Holm computed), one worker per backend so per-trial recordings replay in order, and frozen fixes. Recorded answers sit at the scorer's edges: 0.4% and 0.6% off a 0.5% tolerance, permuted rows on ordered and unordered questions, an extra and a missing row. `summary.json` and `scores.json` (each record's verdict and mismatch reason) must match byte for byte; tolerance ×10, ignoring or forcing `ordered`, and relaxing the row-count check each fail it. The project's real code runs end to end over the fakes; A2.1/A2.2 live recordings replace `recording.json`.
- **Exit codes.** 0 ok; 1 parity, gold, freeze or probe failure (and `pack check` issues); 2 configuration or runtime error (any unexpected exception in any command is one redacted line, no traceback); 3 cost cap.
