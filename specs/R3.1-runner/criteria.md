# R3.1 acceptance criteria

**RUN-01** `run_benchmark` and `agentic-analytics run --backend --fix --trials` fan out backend × question (and probe, for the backends it names) × fix set (the baseline plus each fix alone; Cortex gets the baseline only) × trial, one job each; `--backend all` keeps the backends whose engine is configured and a named backend without its engine is exit 2; each backend runs in its own pool of `concurrency[backend]` workers (a 3/1 configuration peaks at exactly 3 and 1 in-flight model turns), each MCP worker owns one MCP connection and a fresh toolbox per question, and every agent `run_select_query` passes the N1.2 SQL guard before the MCP server (a DELETE is recorded `write_refused` and never reaches the server, D-37); every run (baselines included) refuses with exit 1 before any call unless the fix content matches `fixes/FROZEN.json`; fix runs take F3.1's frozen blocks and self-check hook, and refuse a frozen `fix_hash` other than their cached baseline answers' unless forced with a logged reason; the §9 estimate (model spend, plus the credit-paid warehouse use reported beside it) is printed before the first call, `--dry-run` makes no call, writes nothing and works with no engine or model variables and no snapshot, parity or gold records (OSS-03), a remaining model-spend estimate over `--max-cost` exits 3 with nothing called, and a reservation refused mid-run stops new work and exits 3 with a resume hint after which a rerun completes.

**RUN-02** The answer cache keys on node, `CODE_VERSION`, backend, model snapshot, model parameters (effort; Cortex's semantic view), the ask hash (id and text, not gold), fix set and fix hash, prompt hash, semantic hash (fix runs and Cortex only), snapshot, trial, as-of and loop limits (each input changes the key, a changed effort misses, each trial has its own key; dict ordering never does), never caches transport or timeout failures (a resume retries them), stores Ask plus Execute at `.cache/<k[:2]>/<k>.json` through a temp file and rename (a failed write keeps the old entry and leaves no temp file), and reads corrupt or foreign entries as misses; a rerun is all cache hits with no calls and does not even build services; a run stopped by a config error keeps what finished and the rerun calls only what is missing; `--rescore` rebuilds records and an identical summary from the cache with no calls, and exits 2 if any answer is not cached.

**RUN-03** One writer task appends `records.jsonl` (one schema-valid `Record` per job) and `run.log` (JSON lines from `start` to `finish`, an `ask` event per job with node, `cache_key` (in clear: a field named `key` would be redacted; it names the cache entry) and cache hit, a `score` event with latency and cost, fingerprint events around write probes); log lines and CLI messages pass the redactor (a planted key never reaches disk or the terminal); a failure after the asks still writes `finished_at` and the error into run.json, closes the writer and appends the ledger line; every record is stamped with git sha (of the package's checkout; dirty flag and package version in run.json), prompt, fix and semantic hashes, `gold_check_id`, snapshot sha256 and seed; failures and a deterministic sample are exported as traces under `results/<run_id>/traces/`; `run.json`, `questions.jsonl`, `summary.json` and the dashboard are written, `results/latest` names the run, a run folder is never overwritten, and a spending run appends one spend-ledger line (a cached rerun none).

**RUN-04** A run refuses to start (exit 1, nothing called, no run folder) when the snapshot record is missing, no passing parity record for the current snapshot covers the configured engines (a single-engine record counts only when one engine is configured), parity failed, the pack has no gold check, the gold check failed, is for another snapshot or does not cover a configured engine, a gold result file is missing, or a question or gold file changed after the check (the recomputed `gold_check_id` differs); with one engine configured the summary and dashboard are stamped `single-engine gold`, with two they stay cross-engine.

**RUN-05** `agentic-analytics smoke` runs the first two questions per category of the gold-check selection (12) on every configured backend with one trial, no probes and a $2 model-spend cap, and writes the measured turns and tokens per MCP backend to `cost-assumptions.json`, which every later estimate uses (the estimate changes after a smoke run).

**RUN-06** `report --run latest|ID` renders the run's dashboard from its folder and `report --example` renders the bundled synthetic run with no keys; `reconcile --credits FILE` splits each engine's metered credits over its records in proportion to `warehouse_elapsed_ms`, rewrites records and summary and flips `cost_status` to `reconciled`, and rejects a file missing an engine, a negative or non-numeric value, an unknown engine or a non-object (exit 2); `pack check [--pack PATH]` exits 0 on the bundled pack and 1 with the issues on a broken one; `gold` validates the pack and an existing gold check (0 clean, 1 not clean) and otherwise exits 2 naming Q2.2; `init` writes `run.yaml` (a valid `RunConfig`) and `.env.example` (identical to the repository's) and refuses to overwrite without `--force`; exit codes are 0/1/2/3 as in §4, every command takes `--json`, unknown options on a built command are an error, and an unexpected runtime error is exit 2 without a traceback. Any unexpected exception in any command is exit 2 on one redacted line with no traceback. The golden run (`pytest -m golden`: 3 trials, a fix run, tolerance, order and row-count edge answers) reproduces the stored `summary.json` and `scores.json` byte for byte, twice in fresh folders and once from the cache alone, and fails under tolerance ×10, ignored or forced `ordered`, and a relaxed row-count check.
