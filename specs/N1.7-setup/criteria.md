# N1.7 acceptance criteria

**SET-01** `setup clickhouse` calls only `clickhousectl cloud … --json` through an injected runner, never with `--api-key`/`--api-secret` or any secret in argv, and with `DO_NOT_TRACK=1`. It adopts the one service whose name matches exactly (no `--region` needed; two services with the name are refused) or creates it with `service create --name N --provider aws --region R [--ip-allow CIDR=desc]…`; the one-time admin password is in `.env` before the first `service get`; `service get` is polled until `running` or `idle` (a `stopped` service is started once; `failed` stops; a timeout says to run again and keeps the password); the HTTPS host comes from the `https` endpoint. Fields are found in both a `result`-wrapped and a flat document; a missing field or non-JSON output is a `SetupError` naming the key names seen and no value; exit 4 gives the login hint. An adopted service without `CLICKHOUSE_ADMIN_PASSWORD` is refused unless `--reset-admin-password`, which saves the new password. Invalid options (name, region, provider, IP entries, an empty key allow list, user, role ids) are refused before any call. A second run creates nothing and leaves `.env` unchanged. clickhousectl error text is scrubbed. *Offline proof:* `tests/setup/test_clickhouse_setup.py`.

**SET-02** Unless `CLICKHOUSE_MCP_KEY_ID` and `CLICKHOUSE_MCP_KEY_SECRET` are set (then the key is kept) or `--rotate-mcp-key` is given (then a new one is made and a line says the old one still works), `key create --name agentic-analytics-mcp-<UTC> --role-id <Basic Service API Reader> --ip-allow 0.0.0.0/0=agentic-analytics MCP` is sent (the id of the system org role named exactly "Basic Service API Reader" in `org role list`, read from top-level role records only, a custom role of the same name losing to the system one; or the `--mcp-role-id` UUIDs, which skip the lookup); a missing role, two system roles of that name or a non-UUID id is an error listing the role names seen and asking for `--mcp-role-id`; the progress line names the role used by name, or the given ids; the key id (from `keyId`-like fields only) and secret go straight to `.env`; a reply without both is an error that echoes neither; neither ever appears in output. *Offline proof:* `tests/setup/test_clickhouse_setup.py`.

**SET-03** With the admin password, the admin client receives exactly `CREATE USER IF NOT EXISTS <u> IDENTIFIED BY '<pw>'`, `ALTER USER <u> IDENTIFIED BY '<pw>'`, then the statements of `pack_role_sql(pack, "clickhouse", user=<u>)` (comment lines dropped, split on `;`), with `<u>` from `--ro-user`, `CLICKHOUSE_RO_USER` or `aa_ro_user`; the password is the one in `.env` for the same user, else a new 28-character one with every character class Cloud requires and only `[A-Za-z0-9-_.+]`; it is in `.env` before any statement runs; quotes and backslashes in a reused password are escaped; role SQL that fails `role_sql_problems` is never sent and the admin client is never opened; a failing statement's error names its number and text up to `IDENTIFIED` and never the password. *Offline proof:* `tests/setup/test_clickhouse_setup.py`.

**SET-04** `update_env_file` replaces the first assignment of each name in place (also `export NAME=`), drops later duplicates, appends new names, keeps every other line and comment byte for byte, leaves mode 600, is idempotent (a second identical update changes nothing and returns no names), leaves the old file and no temp file when the rename fails, updates a symlink's target, quotes values so `load_dotenv` reads them back, and refuses values with a line break or NUL naming only the variable. No progress line, error, final text or JSON payload of `setup` holds any planted password, key id, key secret, Cloud API secret, the generated read-only password, the Snowflake password or MFA code, or any line of a private key. `.clickhouse/credentials.json` is git-ignored. *Offline proof:* `tests/setup/test_envfile.py`, `tests/setup/test_cli_setup.py`.

**SET-05** After a successful `setup clickhouse` the text and the `--json` payload carry the console steps equal, word for word, to an independently written copy in the test: turn on remote MCP for the service (`https://mcp.clickhouse.cloud/mcp`), and bind the generic Query API endpoint to the MCP key (its name, or "whose id is CLICKHOUSE_MCP_KEY_ID in .env" when kept) with role `analytics_ro`, not `sql_console_read_only` or `sql_console_admin`; then the admin-key deletion note. No `query-endpoint` command is ever sent. *Offline proof:* `tests/setup/test_clickhouse_setup.py`, `tests/setup/test_cli_setup.py`.

**SET-06** `setup snowflake` creates `admin_key.p8` and `ro_key.p8` (PKCS8 PEM, unencrypted, RSA-2048, mode 600, folder 700) and `*.pub.txt`, never overwrites an existing key (exclusive create; an existing key is reused and a missing public half rewritten from it), and refuses a broken key, an orphan public key and a mismatched public key. The bootstrap SQL holds both public keys, creates the users with `IF NOT EXISTS` plus `ALTER USER … SET RSA_PUBLIC_KEY`, creates the pack's database and schemas as SYSADMIN, contains the read-only role SQL (which passes `role_sql_problems`; a widened one is refused) and ends with the `SNOWFLAKE_ACCOUNT` row. Print mode prints it with the Snowsight steps and the `.env` lines, saves it, connects nowhere and leaves `.env` alone. `--run` connects once with `account`, `user`, `password`, `role=ACCOUNTADMIN`, `authenticator=username_password_mfa`, `login_timeout=120` and `passcode` (left out when the MFA prompt is empty, for a Duo push), runs the SQL with `execute_string`, writes the account and the five other Snowflake lines to `.env` (other lines kept, mode 600), then logs in as each user with `SNOWFLAKE_JWT` and `private_key_file`, requiring `CURRENT_USER()` to match. A login failure is scrubbed of the password and code; an empty password never connects. *Offline proof:* `tests/setup/test_snowflake_setup.py`, `tests/setup/test_cli_setup.py`.

**SET-07** `run_doctor(..., mcp=query)` sends exactly `SELECT currentRoles() AS roles, getSetting('readonly') AS readonly` and reports `clickhouse.mcp_role` PASS only when the roles are non-empty and all `analytics_ro` and readonly is 1 or 2 (D-64; a JSON list, a JSON string or ClickHouse array text all parse); `sql_console_*`, extra roles, no roles, readonly 0 or missing, an unreadable result, a tool error and an exception all FAIL with the roles or the error shown, scrubbed of every environment value; the check is absent unless asked and SKIP with `check_mcp=True` and no MCP variables; `mcp_query` runs it through the N1.5 client against an in-process MCP server with the service id injected; `agentic-analytics doctor --json` reports it. *Offline proof:* `tests/setup/test_doctor_mcp.py`.
