# A2.3 — Answer assembly and tracing

**Wave 2. Depends on:** A2.1, A2.2 (Cortex parser not built yet; the Cortex path is covered through `AnalyticsAnswer` fixtures). **Unblocks:** R3.1, B3.1, D4.1.

## Goal
Every backend's answer leaves Ask in the same shape, `{sql, answer, chart}`, with the chart built by one deterministic builder from the executed rows (D-6), and every run leaves a trace: a Langfuse trace per (run, question, backend, fix set, trial) and a JSON copy in the run folder for failures and samples (D-16), with no secret in either (NFR4).

## Outputs
- `agentic_analytics.answer.chart_for(result, question_text=None, *, rows_total=None)` (ANS-01): Vega-Lite v5 with inline values. One non-boolean cell gives a KPI text mark. A period column plus one numeric measure gives a line sorted by period; a period is all-`YYYY-MM-DD` or all-`YYYY-MM` ISO strings (temporal, UTC scale and UTC time unit), integers in a column with a `year`/`yr` name token, or distinct strictly consecutive integers in 1990–2100 in a column with no id/code/amount-like name token. One text column plus one numeric measure gives a bar chart sorted descending, cut at 25 bars with "top 25 of N" in the title. Anything else gives `None` and the table is shown: empty, one row of two or more values (D-70), truncated (`rows_total` above the rows held), nulls, booleans, nested values, integers beyond 2^53, repeated periods or labels, two or more measures, extra columns. Fields are renamed to `period`, `label` and `value`; the original names are axis titles.
- `agentic_analytics.answer.assemble(answer, execution)` (ANS-02): sets `chart` from a successful execution of the answer's own SQL, passing its `rows_total`, re-validated through `AnalyticsAnswer.model_validate`; with no SQL or a failed execution the chart is cleared. `with_trace(answer, trace_url, trace_export)` records where the trace went.
- `agentic_analytics.tracing` (ANS-03): `TraceKey`, `Span`, `Trace`, `build_trace` and `trace_from_record`; the `Tracer` protocol (`send(trace) -> url | None`, `flush()`), `NoopTracer`, and `LangfuseTracer` over the Langfuse v3 SDK, imported lazily (the package is not a dependency; a missing package raises `TracingUnavailable`). One generation span per model turn (tokens, cost, latency, request id), one tool span per agent step, one Cortex span carrying `request_id`, one execution span, each with start and end offsets laid end to end. With the turns given, a `final_answer` tool span takes no time (its latency is its turn's, A2.1) and keeps it as `turn_latency_ms` (D-70). Sample traces are `public`.
- `export_trace(trace_or_record, results_dir)` (ANS-04): writes `results/<run_id>/traces/<qid>-<backend>[-<fixes>]-<trial>.json` with sorted keys and UTF-8, returning the path relative to the results folder's parent for `AnalyticsAnswer.trace_export`; `select_for_export` picks failures and a deterministic sample.
- `Redactor` (ANS-05), applied to every export and every value sent to a tracer. On strings: each secret env value in its raw, JSON-escaped (once and twice) and URL-encoded (once and twice, `+` or `%20` for a space, `/` encoded or kept, percent hex in any case) forms, anywhere when 8+ characters and as a whole token when shorter (`DEMO_PASSCODE=482` scrubs "482" in text but not "4821"); PEM blocks; Authorization, Proxy-Authorization, X-Api-Key, api_key, Cookie and Set-Cookie values, and password / passwd / pwd values (also ending a longer name: `PGPASSWORD=`, `db_password=`), in any case, quoted, escaped or bare; URL query `token`, `access_token`, `key`, `sig`, `signature`, `password` and similar, including names ending in one of those words after `-`, `_` or a camelCase hump (`client_secret`, `X-Amz-Signature`, `accessToken`, D-70), after `?`, `&`, `#` or `;`; bare Bearer/Basic credentials; the `scripts/secret_scan.py` patterns (copied, pinned by a test). In structures: values under keys like *token* (not *tokens*), *secret*, *password*, *passcode*, *credential*, *api_key*, *access_key*, `key`, `authorization`, `cookie` are replaced whole, and a string holding JSON is decoded, scrubbed and re-encoded. Numbers are never changed, so a numeric secret never corrupts a result cell. Not covered (documented on `Redactor`): a secret base64- or hex-encoded, split across fields, or encoded another way, and a secret-named word in prose outside a header, password or query position.

## Assumed Langfuse API (v3, not installed)
`Langfuse(public_key=, secret_key=, host=)`; `client.start_span(name=, input=, output=, metadata=, trace_context={"trace_id": id})` returns a span with `update_trace(name=, session_id=, tags=, public=, input=, output=, metadata=)`, `start_span(...)`, `start_generation(name=, model=, input=, output=, usage_details=, cost_details=, metadata=, level=, status_message=)`, `end(end_time=<epoch ns>)`; `client.get_trace_url(trace_id=)`; `client.flush()`. Pin `langfuse>=3,<4` when installed. v3 takes no start time when a span is created, so each span is ended `latency_ms` after its creation to give Langfuse the real duration; its place in the run goes in metadata (`start_offset_ms`, `end_offset_ms`, and `start_time`/`end_time` when the trace start is known), approximate because spans are laid end to end in span order. The live test checks all of this against the real SDK.

## Out of scope
Calling the tracer and exporter from the run loop and choosing the sample rate (R3.1); the dashboard's rendering of exports (B3.1); the Cortex parser (A2.2).
