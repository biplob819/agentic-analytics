# F3.1 — Fixes as flags

**Wave 3. Depends on:** A2.1, N1.4, Q2.2. **Unblocks:** F3.2. Built right after the gold check code and frozen before any baseline run (OWNER D-13).

## Goal
The three fixes of Tech Spec §7 as frozen, hashed content the runner can switch on one at a time: `descriptions` (the N1.4 semantic block), `examples` (five verified question-and-SQL pairs) and `self-check` (implausibility rules with one feedback turn inside the call budget), plus the leak check that keeps the examples from paraphrasing or answering the benchmark, and the freeze record gate 8 checks.

## Outputs
- `packs/uk_price_paid/fixes/examples.yaml`: five ClickHouse lookups and listings `ex-1`…`ex-5` that teach conventions without the scored output formulas (D-52): the districts of a post town (uppercase place names), the stored type and tenure values (enum values, `toString` ordering), Cumbrian localities whose exact median exceeds £400k in 2018 (`quantileExactInclusive` in a HAVING, no measure returned), sales on one street in 2019 (half-open date filter), and postcodes of new-build leasehold flats in one month (`is_new`, `duration`, `BETWEEN` dates).
- `packs/uk_price_paid/fixes/self_check.yaml`: thresholds (price level £1k–£10m, ±500% on explicit `pct_change`/`yoy_pct` columns), the stats query, column-name patterns and message templates for eight rules.
- `packs/uk_price_paid/fixes/FROZEN.json`: the freeze record (`fix_hash 7ae1907888981…`, the D-48 re-freeze after OWNER D-67, with `frozen_at` and `reason`).
- `agentic_analytics.fixes`:
  - `examples`: `load_examples(pack)`, `parse_examples`, `examples_block(examples)` (the prompt text), `lint_example(example, ctx)` (Q2.1's ClickHouse writing rules), `FixError`.
  - `leak`: `overlap`, `text_leaks(examples, questions)`, `skeleton(sql)`, `structural_leaks(examples, questions, probes)`, `result_leaks(example_results, gold)`, `execute_examples(executor, examples)`, `result_leaks_live(executor, examples, gold)`.
  - `self_check`: `SelfCheckRules`, `load_rules(pack)`, `judge(sql, result, rules, stats, expects_empty=)`, `make_self_check(executor, rules) -> async hook(sql, *, expects_empty=False) -> str | None`.
  - `freeze`: `fix_hash(pack)` / `current_fix_hash(pack)`, `frozen_fix_hash(pack)`, `fix_blocks(pack)`, `freeze_fixes(pack, force=False, reason=None)`, `frozen_problems(pack)`, `fix_hash_matches_frozen(pack)`; `python -m agentic_analytics.fixes [--pack P] [--force --reason R] [--check]`.
- Tests in `tests/fixes/`.

## Design decisions
- **descriptions = SEM-03, nothing added.** `descriptions_text(pack)` is `semantic.descriptions_block(load_semantic(pack))`, so the agents see exactly what Cortex's semantic view carries (C6, D-8).
- **Examples teach conventions, not scored formulas (D-52).** The first draft's examples (an average for a town and year, medians per district, a top 3 with a tie-break and LIMIT, a two-year percentage change) mirrored benchmark gold patterns even about other places. They were replaced by lookups and listings that show uppercase place names, enum values, exact functions (inside a HAVING, no measure returned), date filtering, the new-build flag and tenure. Each example passes Q2.1's single-engine ClickHouse rules and none equals a gold query. Residual format teaching (`ORDER BY toString(type)`, half-open date ranges, `!= ''` exclusions) remains and must be disclosed in the report.
- **Leak overlap is measured against the smaller 3-gram set.** §7 says "share more than half its normalised word 3-grams"; dividing by the smaller of the two sets also catches a short benchmark question copied inside a longer example (the first draft of `ex-1` scored 0.60 against `q-113` this way and was reworded). Normalisation: casefold, every non-alphanumeric run becomes a space. All 120 bank questions are compared, ambiguous ones included, not only the selected 100. The bundled examples peak at 0.17.
- **Structural leak (D-52).** Each SQL becomes a token skeleton (literals `?`, identifiers `c`, `AS alias` dropped, functions and keywords kept). An example leaks when its skeleton equals, or shares more than half its distinct 6-grams (over the smaller set) with, the skeleton of any gold SQL, ambiguous interpretation or probe gold (ClickHouse). All four first-draft formula examples score 0.74–1.00 and are caught (planted in the tests); the replacements peak at 0.50 (ex-1 against p-id03/04/05: generic `FROM uk.uk_price_paid WHERE town` boilerplate, allowed because the rule is a strict `>`).
- **Result leak is the scorer's equality.** An example's result equals a gold result when S2.1's matcher accepts it in both directions at an exact tolerance with equal column counts and order ignored, so renaming a column or reordering rows does not hide a copy. It needs the examples executed, so it is live-only.
- **Self-check judges from the SQL and the result, read-only, with few false positives.** The hook runs the agent's final SQL once through N1.2's executor (guard first; row cap 1,000) in a worker thread, and reads the table's row count and date range once per hook with `stats_sql`. Rules: `zero_rows` and `zero_aggregate` (every number 0), both skipped when the question `expects_empty` (the hook takes `expects_empty=`; the runner binds it per question); `null_aggregate` (aggregates found from the parsed projection); `price_out_of_range` only for column names that denote a price level (avg/mean/median + price, not change/diff/pct/ratio/share/`_k`), £1,000–£10m (1995 street medians can be a few thousand pounds); `count_above_rows`; `date_out_of_range` (ISO dates, and years from `toYear` or a column named `year`); `change_beyond_limit` only for columns named `pct_change` or `yoy_pct` beyond ±500%; `execution_failed` on a SQL error or guard refusal (transport failures and timeouts give none). A test runs the rules over a plausible result of every shipped gold answer's shape and finds no hit; a live test reports the false-positive rate over the real gold. The hook uses a threading lock, not an asyncio one, so it can outlive one event loop. The call cap is A2.1's.
- **The freeze covers what the model sees.** `fix_hash` = sha256 of canonical JSON over each fix file's text, the RENDERED `fix_blocks(pack)` (descriptions block, examples header and body, self-check rules text) and the self-check rules as loaded, so a renderer change with no file change (a new header sentence in `examples_block`) changes it and fails `--check`. `FROZEN.json` stores per-file and per-block hashes so `frozen_problems` names what changed, plus `frozen_at` and a `reason`. `freeze_fixes` refuses to overwrite unless `force`, and a forced re-freeze needs a reason (`--force --reason D-nn`).
- **Runner hand-off.** `fix_blocks(pack)` returns the strings `RunOptions.fix_blocks` takes, `make_self_check(services.clickhouse, load_rules(pack))` is the `Services.self_check` hook (bind `expects_empty` per question with `functools.partial`), and `frozen_problems(pack)`, `current_fix_hash(pack)` and `frozen_fix_hash(pack)` are what the runner's freeze checks call. The checks themselves (refuse a baseline without a freeze; refuse a fix run whose fix_hash differs from its baseline records' unless forced with a logged reason) belong to the runner (R3.1), not to this node.

## Offline vs live
Offline: FIX-01, FIX-02 (content and lint), FIX-03 text and structure rules and the result rule's comparison, FIX-04 (including the no-false-positive sweep over shipped gold shapes), FIX-05. Live-only: executing the five examples on ClickHouse (non-empty, under 200 rows) and the result-set leak check against the real gold (`tests/fixes/test_examples.py::test_live_examples_run_nonempty_and_leak_no_gold`, `tests/fixes/test_leak.py::test_live_no_example_result_equals_a_gold_result`), and the self-check false-positive rate over the real gold (`tests/fixes/test_self_check.py::test_live_false_positive_rate_over_real_gold_results`), all after `agentic-analytics gold` has run.
