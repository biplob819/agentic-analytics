# F3.1 acceptance criteria

**FIX-01** The `descriptions` fix text is exactly `semantic.descriptions_block(load_semantic(pack))` for the pack (the SEM-03 block, starting with its title line), and `fix_blocks(pack)` returns it under `descriptions` together with non-blank `examples` and `self_check` entries. *Proof:* `tests/fixes/test_examples.py::test_descriptions_fix_is_the_semantic_block`, `test_fix_blocks_cover_every_fix_name`.

**FIX-02** `fixes/examples.yaml` validates (`schema_version 1.0`, `engine: clickhouse`, unique `ex-n` ids, no unknown keys, no duplicate YAML keys) into exactly five distinct question-and-SQL pairs that teach conventions (uppercase place names, enum values, exact functions, date filtering, the new-build flag, tenure) through lookups and listings without returning a scored measure (D-52); each SQL passes the N1.2 guard and every Q2.1 single-engine ClickHouse writing rule (a planted `median()` and a lowercase town are caught), and none equals a benchmark gold query; `examples_block` lists the pairs in order under `VERIFIED EXAMPLES` and `BLOCK_INTRO`. Live (2026-11-17, `docs/measurements/fixes-live-2026-11-17.json`): each example runs on ClickHouse and returns 1–200 rows. *Proof:* `tests/fixes/test_examples.py` (`test_bundled_pack_has_five_examples`, `test_examples_pass_the_clickhouse_writing_rules`, `test_example_lint_catches_an_approximate_median_and_lowercase_town`, `test_examples_are_not_benchmark_gold`, `test_examples_block_holds_each_pair_in_order`, `test_malformed_examples_file_is_refused`); live `test_live_examples_run_nonempty_and_leak_no_gold`.

**FIX-03** No bundled example's normalised word 3-grams overlap any of the 120 benchmark questions by more than 0.5 (shared over the smaller set); a planted paraphrase of `q-062` and a short question copied inside a long example are `text` leaks, and exactly 0.5 is allowed. No bundled example's SQL skeleton (literals `?`, identifiers `c`, aliases dropped) equals or shares more than half its 6-grams with any gold SQL, ambiguous interpretation or probe gold; each of the four first-draft formula examples (town-year average, medians per district, top 3 with tie-break and LIMIT, two-year percentage change) planted back is a `structure` leak, and interpretations and probe gold are compared. A result set equal to a gold result, even with renamed columns and reordered rows, is a `result` leak; a different value or a superset is not; examples that fail, return no rows or exceed 200 rows are reported. Live (2026-11-17): no example's result set equals any gold result of the selected questions. *Proof:* `tests/fixes/test_leak.py` (`test_bundled_examples_do_not_leak_the_benchmark_text` and `test_bundled_examples_do_not_mirror_any_gold_sql_structure` are `@pytest.mark.gold`, `test_planted_formula_mirrors_are_structural_leaks`, `test_ambiguous_interpretations_and_probe_gold_are_compared_too`, `test_skeleton_strips_literals_identifiers_and_aliases`, `test_planted_paraphrase_of_a_benchmark_question_is_a_leak`, `test_equal_result_set_is_a_leak_even_with_renamed_columns_and_reordered_rows`); live `test_live_no_example_result_equals_a_gold_result`.

**FIX-04** `fixes/self_check.yaml` holds the thresholds (price level £1,000–£10,000,000; ±500% on `pct_change`/`yoy_pct`) and a message for each of eight rules; malformed thresholds, unknown placeholders, missing messages and bad patterns are refused. `make_self_check(executor, rules)` returns an async `hook(sql, *, expects_empty=False) -> str | None` that runs the SQL once through the read-only executor (a write is refused by the guard), reads the table stats once, and returns one message (preamble, one line per rule hit, closing) when any rule fires: zero rows or every number 0, unless `expects_empty`; a NULL aggregate (not a NULL group key); a price-level column (by name; changes, ratios, totals, `min_price` and unnamed columns exempt) outside the range; a count above the table's rows; a date or 4-digit year outside the data range (a count in `sales_last_year` is not a year); an explicit percentage-change column beyond ±500; a SQL error or guard refusal. Plausible results, transport failures and timeouts return None; a failed stats query skips only the two rules that need it; a non-ClickHouse executor is refused. Over a plausible result of each of the 100 shipped gold answers' shapes no rule fires. In A2.1's loop the message is sent once and the next final answer stands. Live (2026-11-17): the false-positive rate over the real gold results is reported (at most 5%); measured 0/84 with all eight rules, the real table stats included (31,702,685 rows, 1995-01-01 to 2026-09-30). The hook runs the agent's SQL once per call under the 1,000-row cap, fetches the stats only for a query that ran, and retries a failed stats query on the next call. *Proof:* `tests/fixes/test_self_check.py` (one planted defect per rule, `test_zero_rows_unless_the_question_expects_empty`, `test_zero_aggregate_when_every_number_is_zero`, `test_price_rule_only_for_names_that_denote_a_price_level`, `test_no_false_positives_on_the_shape_of_every_shipped_gold_answer`, `test_hook_takes_the_questions_expects_empty_flag`, `test_hook_drives_one_feedback_turn_in_the_agent_loop`, `test_malformed_rules_are_refused`); live `test_live_false_positive_rate_over_real_gold_results`.

**FIX-05** `fix_hash(pack)` (= `current_fix_hash`) covers each fix file's text, the RENDERED `fix_blocks(pack)` and the self-check rules as loaded: it changes when any character of a fix file's text changes (read as text, so a line-ending-only change such as CRLF does not count: the model sees the same text), the descriptions block or a rendered block changes, including a new `examples_block` header sentence with no file change (which also fails `--check`). `freeze_fixes(pack)` writes `fixes/FROZEN.json` (`kind fix_freeze`, pack, `fix_hash`, per-file and per-block sha256, rules sha256, `frozen_at`, `reason`), refuses when the record exists unless `force`, refuses a forced re-freeze without a reason (CLI: `--force` needs `--reason`), and refuses malformed fix files; after a freeze, editing a fix file, a threshold or the semantic text makes `fix_hash_matches_frozen` false and `frozen_problems` name each changed file and block; `frozen_fix_hash` returns the frozen value (None when not frozen); a missing or corrupt record is reported. The bundled pack's fixes match its frozen record (gate 8, `@pytest.mark.gold`). *Proof:* `tests/fixes/test_freeze.py` (`test_bundled_fixes_match_the_frozen_record`, `test_hash_covers_the_rendered_blocks_and_the_loaded_rules`, `test_changed_examples_header_changes_the_hash_and_fails_the_check`, `test_changed_fix_file_after_freeze_fails_the_gate`, `test_changed_threshold_or_semantic_text_after_freeze_fails_the_gate`, `test_freeze_writes_the_record_and_refuses_to_overwrite`, `test_module_entry_point_freezes_and_checks`).
