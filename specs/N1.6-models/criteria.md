# N1.6 acceptance criteria

**MOD-01** For Claude the request carries the model, `max_tokens`, system, tools (`input_schema`, `strict` when asked), the history, top-level automatic `cache_control` and `output_config.effort`, and never `temperature`, `top_p` or `top_k`; a response is parsed into text, tool calls, a stop reason (`tool_use`, `end`, `refusal`, `max_tokens`; a context-window cut-off or any unknown stop reason counts as `max_tokens`, so its tool calls never run) and usage where the prompt includes cache reads and writes and thinking is split from output; the assistant content (thinking blocks and explicit nulls included) is appended to the history exactly as the API sent it; tool results go back as `tool_result` blocks with `is_error`; a follow-up user text joins the last user turn.
**MOD-02** For GPT the Responses API request (D-54) carries the model, `instructions` (the system prompt), `input` (the history), flat function `tools` with an explicit `strict` (omitted entirely when there are none), `max_output_tokens`, `reasoning.effort`, `store: false` and `include: ["reasoning.encrypted_content"]`, and never sampling parameters or `previous_response_id`; `function_call` items are parsed with JSON arguments, and arguments that are not a JSON object give `parse_error` instead of an exception; text is the concatenated `output_text` parts; a refusal part or a `content_filter` cut-off maps to `refusal` with its category, any other incomplete or unknown status to `max_tokens` (its tool calls never run), function calls to `tool_use`, otherwise `end`; usage reports the whole prompt (cached and cache-write included), visible output without reasoning, reasoning and cached tokens; the response's output items (reasoning items with their encrypted content included) are appended verbatim, then one `function_call_output` per result and `user` messages for follow-up text; deeply nested or invalid arguments never crash; a live round trip (one tool call at effort low) passes.
**MOD-03** `prices.yaml` prices both benchmark models (Sonnet 5.5 cache reads at $0.10/M) with a check date and source; `credits.yaml` holds exactly the four rates, each with a real boolean `verified` flag and a source, the Cortex rate being 0.067 credits per message from the consumption table effective 2026-11-12; malformed or incomplete rate files are errors; an unknown model fails when the adapter is built, not mid-run.
**MOD-04** Per-turn cost equals EvalKit's `call_cost` on the parsed usage; `estimate_run` multiplies by trials and by fix sets for MCP agents only, adds Cortex message and Snowflake warehouse credits and ClickHouse compute dollars, matches the §9 formula in absolute value, and lists unverified rates; `SpendCap` hands out reservations that settle exactly once, allows reaching the cap exactly, refuses a reservation that would take spent plus in-flight past it, never lets concurrent reservations exceed it together, and rejects NaN, infinite, negative or zero caps and costs.
**MOD-05** Calls retry transient failures (429, 5xx, connection) for at most six attempts with the SDK clients built with `max_retries=0`, and never retry a 4xx config error or an out-of-quota 429; `classify_error` calls authentication, permission, payment/quota, bad-request, too-large and not-found errors `config` and exhausted transient failures `transport`.
**MOD-06** `append_ledger` appends one sorted-key JSON line with timestamp, kind, run id, rounded spend and credits, creating the folder if needed, and refuses non-finite or negative amounts.
