# A2.1 — MCP agent loop

**Wave 2. Depends on:** N1.5, N1.6. **Unblocks:** A2.3, F3.1.

## Goal
One tool loop drives Claude and GPT through the same hashed system prompt, the same three MCP read tools and a typed `final_answer`, inside hard budgets (6 MCP calls, 10 model turns, 120 seconds), and returns a schema-valid `AnalyticsAnswer` with every step recorded, plus the run's cost and tokens.

## Outputs (`agentic_analytics.backends`)
- `prompts.py`: `PROMPT_VERSION`, `BASE_PROMPT` (rules B1–B9 in plain words), `as_of_line(as_of)` (D-10), `render_system_prompt(as_of, fix_blocks)` (fix blocks after the base prompt and the as-of line), `FINAL_ANSWER_SPEC` (strict, `additionalProperties: false`), `prompt_hash(as_of, mcp_tools)` (AGT-01, AGT-02, AGT-03).
- `mcp_agent.py`: `ask_mcp(question_text, *, model, toolbox, as_of, fix_blocks=(), max_turns=10, wall_s=120, self_check=None, clock=time.monotonic) -> AgentRun` and `AgentRun(answer, cost_usd, tokens, turns, self_check)` (AGT-01..05).
- `tests/backends/test_live_smoke.py`: 3 questions on both models through the real MCP server, `live` and skipped unless `AA_LIVE=1` (AGT-06).

## Decisions
- **Backend name** comes from the adapter's `provider`: `anthropic` → `claude_mcp`, `openai` → `gpt_mcp`; anything else is a `ValueError` before any call.
- **Prompt hash** = sha256 of canonical JSON `{version, system, tools, loop}` where `system` is the rendered prompt *without* fix blocks (they carry their own `fix_hash`, D-1) and `tools` is every spec the model is offered (the toolbox's three plus `final_answer`), in order. `loop` holds the loop's own model-facing texts (`REMINDER`, `ACCEPTED`, `REJECTED`, `DUPLICATE`, `GUARD_REFUSAL`, kept in `prompts.py`); the toolbox's refusal texts are N1.5's. A changed MCP tool description or loop text therefore changes the hash.
- **Errors** (`AnalyticsAnswer.error`): `refusal` stop → `refusal`; `max_tokens` stop (output cut, context window full, or an unknown stop reason) → `step_budget`, because a resource limit was hit and its tool calls cannot be trusted; provider failures that `classify_error` calls `transport` → `transport`; `config` errors are re-raised (EK L-21); turn cap, wall clock, or a second turn that calls MCP after the budget was spent → `step_budget`; a second `final_answer` violation, or no `final_answer` after one reminder → `schema`. `timeout` is left for the live demo (§2.6).
- **Over-budget calls.** The toolbox refuses the 7th call with a tool error telling the model to call `final_answer` (§2.4 diagram). The model gets that one turn of grace; if a later turn calls MCP again, the question ends with `step_budget`.
- **Steps.** One `AgentStep` per tool call in call order, `final_answer` included. `error` is `"<code>: <detail>"` with the codes of `scoring/policy.py`: the toolbox refusals (`budget`, `not_allowed`, `bad_args`), `write_refused` for a failed call whose query is a write or whose error says read-only, `sql_error` for any other server-side failure (MCP transport failures included, detail says which), `bad_args` for a rejected `final_answer`. Latency: the toolbox round trip for MCP calls; the producing model turn for `final_answer`.
- **Tokens.** Each model turn's tokens go to the first step that turn produced (`tokens_out` = visible + reasoning); later steps of that turn get zero. Turns that produce no step (reminder, refusal, cut-off) appear only in `AgentRun.tokens`. `AgentRun.tokens` has `in`, `out`, `reasoning`, `cached`, `cache_write`; `cost_usd` is the `math.fsum` of turn costs (EK L-27).
- **Parallel calls** run one at a time in the order sent; all results go back in one batch. A turn with a valid `final_answer` ends the question after its batch; any MCP calls in the same turn still run and are recorded. `final_answer` calls in a turn are judged in order until one is accepted (each rejection is a violation); later ones are recorded as `bad_args` duplicates and ignored.
- **Self-check hook.** After the first valid `final_answer` with SQL, `await self_check(sql)` runs under the wall clock (a hook timeout marks the check `skipped` and the answer stands). A blank or None result is `passed`. A message is sent once as a user turn only if the toolbox has calls left, a model turn remains and at least `self_check_min_s` (default `FEEDBACK_MIN_S` = 20 s) of wall clock remains; otherwise `skipped` and the first answer stands. The next `final_answer` is final. If the follow-up overruns a budget (`step_budget`: wall clock, turns or calls), the first valid answer is returned instead, with every step kept; any other failure after feedback (schema, refusal, transport) ends the question with that error.
- **Reopen (N1.5).** The toolbox never reopens; it flags `conn.needs_reopen`. The loop owns the connection's task, so before any turn with MCP calls it awaits `conn.ensure_open()` once (within the wall clock); a failure ends the question with `transport`. A connection that drops mid-batch is reopened before the next turn.
- **SQL guard (D-37).** `ask_mcp(..., guard=None)` takes `guard(query) -> reason | None`. It runs on `run_select_query` only, before the toolbox. Within budget, a refusal adds one to `toolbox.calls_made` (the single counter the budget and self-check read), goes back as a tool error, never reaches the server and is recorded as `write_refused` if `is_write_sql(query)`, else `guard` (`STEP_ERROR_GUARD` in `scoring/policy.py`). Past the budget the toolbox's `budget` refusal comes first and the guard is not asked. The guard is not part of the prompt, so the prompt hash does not change with it. A guard that raises escapes `ask_mcp` and stops the run: a guard bug is a config error, never a scored failure. R3.1 wires `check_sql`; backends never import `warehouse/`.
- **Error answers** carry `sql=None`, `answer=""` (a refusal keeps the model's text), and every step recorded so far.
