# D4.2 — Demo page

**Wave 4 (Should, US7). Depends on:** D4.1 (`ask_panels`, guard, warm-up, replay cache), B3.1 (licence credit wording, chart conventions). **Unblocks:** nothing (last node).

## Goal
PRD Flow B as a Streamlit page, deployed as its own Streamlit Community Cloud app from this repo (D-57; first planned for a shared `portfolio-demos` app): it opens on a sample question already answered on both backends, shows two panels (SQL, answer, chart, cost, trace link), offers passcode live mode with today's budget, and carries the licence credit and the honest Cortex line. Streamlit comes only with the optional `demo` extra (D-57), never as a core dependency: the page imports it only when run, and all logic is pure functions tested without it.

## Decisions
- **Lazy Streamlit.** `page.py` has no top-level streamlit import (`importlib.import_module("streamlit")` inside `main`); the layout calls a small set of Streamlit functions on whatever `st` it is given, so `FakeSt` exercises the whole page in tests. No `st.cache_resource`: one guard and one live context per process are cached in module state (`shared_live`), which also shares the rate-limit memory across sessions. The extra is `pip install agentic-analytics[demo]` (streamlit, psycopg), declared with D-57.
- **Which replay file.** `AA_DEMO_CACHE`, else `demo/replay.json` in the working folder, else the bundled SYNTHETIC example (so the page works with no keys). A synthetic cache shows its label as the first banner line (the default SYNTHETIC label when its own is blank or does not say SYNTHETIC). A replay file that fails to load (for example entries that disagree with its config) shows an error and the labelled example instead.
- **Opening (DEM-01).** The sample select box opens at index 0, the first question answered on every backend, rendered from replay with no call; `replay_view` shows the picked sample through `opening(cache, pick)`.
- **Panels (DEM-02).** Title (backend label and model snapshot), any error in words (timeout, refusal, budget stop, SQL failure), the answer or clarification and suggestions as escaped text (model text never becomes markup or links), SQL in a code block, the Vega-Lite chart (`st.vega_lite_chart`, plain JSON) or else the first 20 rows in `st.dataframe` with "First n of N rows" (plain text: executed cells and column names come from model-written SQL, and `st.table` renders GFM in both), the as-of date ("Data as of 2026-09-30", D-50) on every panel, the cost and latency line ("Synthetic cost … · synthetic latency …" on synthetic panels), the trace link (`[Trace](url)`, the exported path, or why there is none: synthetic, or live visitor questions are not traced), and notes (the Cortex line on every Cortex panel, the cost-cap stop). Every shown string passes the trace `Redactor` (secret patterns; in live mode also the deployment's secret values) as defence in depth.
- **Live mode (DEM-03).** Off with a plain warning when the page shows the synthetic example (its as-of date and models are fake), when there is no readable `run.yaml` (`AA_RUN_CONFIG` overrides the path), when `run.yaml` disagrees with the replay answers on models, effort, as-of date, pack version or fix_hash (the warning names the fields), or unless `DEMO_PASSCODE` and the engines the panels need are configured (`live_problem`, names nothing secret). Live services are built from `run.yaml`'s config (`live_settings`, `build_live`), never from the replay file's. ClickHouse is warmed (D4.1 `warm_up`, on a background thread, once per session, itself limited per process) only after the visitor's passcode passes the guard's check, so an unauthenticated visitor triggers no model or warehouse call. The budget line reads "Today's live budget left: $x of $3.00, shared by all visitors and the real limit · each request holds at most $1.00 · 5 live questions per hour per session" ("unavailable" when the store is down; "(local counter)" with SQLite): the rate limit lives in the browser session (a reload starts a new one), so the $3 daily cap is the real bound. The form takes the passcode and a question (500 characters); refusals show the guard's message; an unexpected failure shows a generic message and logs its type only. After an answer: "This question cost $… (held at most $…)".
- **Banner (DEM-04).** `st.info` lines: the synthetic label (when synthetic), the pack's licence credit from the cache ("Contains HM Land Registry data © Crown copyright and database right 2021. This data is licensed under the Open Government Licence v3.0."), and exactly "Cortex Analyst returns SQL; its answer text here is a template over the rows it returned."
- **Deployment (DEM-05; D-93 split the deployed live p95 into DEM-15 under B3.3).** Documented in the module docstring: install with the `demo` extra, point the app at the repo-root `demo/app.py` (D-57; first planned as the shared `portfolio-demos` app), put `DEMO_PASSCODE`, `EVALKIT_DEMO_DATABASE_URL`, the model, ClickHouse MCP and read-only executor variables and the Snowflake read-only key pair in the host's secret store (`SECRETS`, never an `*_ADMIN_*` one); `secret_env` reads `st.secrets` (string values only) over the environment. `measure_p95(ask_one, questions, n=20)` times 20 asks from submit to last panel (nearest-rank p50/p95 via `evalkit.stats.percentile_ms`). Panels are cut at 25 s, so p95 < 30 s alone proves nothing: it passes only with ≥ 20 asks, p95 < 30 s, no timed-out and no errored panel and no stop (spend cap or refusal); the report lists timed-out and errored panels, the spend and the latencies.
- **What the p95 measures.** `python -m agentic_analytics.demo.p95` has two modes. `--mode page --url https://<deployed page>` (an https URL is required) is the DEM-15 proof (B3.3, D-93): a headless browser (Playwright, on the measuring machine only) opens the deployed page over HTTPS in a fresh session per ask, submits passcode and a sample question, and times click to the request's cost line. `--mode in-process` times `ask_panels(..., "live")` on the owner's machine and is labelled a diagnostic, not DEM-05. Both refuse to start when `n` × the request's hold (from `run.yaml`) exceeds `--max-cost` (default $15; above $25, the owner-approval threshold, refused), stop an ask that would pass the cap, and write `docs/measurements/demo-p95-<date>-<mode>.json` with the mode, URL or host, backends, models, as-of date, commit, `n` requested and done, hold, cap, spend and report. Page mode's timing (submit to answer, page load and typing excluded) is tested offline against a stand-in `playwright.sync_api`; the deployed page is measured live under DEM-15.

- **Visitor own keys (OWNER D-56, D-61; DEM-06..DEM-09).** With an own-key limit configured (`build_live` always makes one), live mode shows the notice, the own-key budget line ("Own-key questions: warehouse limit left today $x of $5.00, shared by all own-key visitors · 5 own-key questions per hour per session") and one password field per provider that serves a live agent panel ("Your Anthropic API key (optional, Claude panel)", "Your OpenAI API key (optional, GPT panel)"); no field label contains "passcode" or "your question" and no button "Ask both backends", so p95 page mode's selectors stay unique. The submit callback moves typed keys into a pending slot and empties the widgets. After the submit, the passcode decides: a wrong one drops the typed key; the owner passcode drops it with a note and runs on the owner's keys (stored keys are ignored); the visitor passcode accepts it (`accept_keys` with the deployment's own keys refused; a malformed key shows its reason and asks nothing) and keeps the session's `VisitorKeys` in `st.session_state`, merged per provider with any stored one. The page's `Redactor` gets the stored and typed keys for that run. A panel paid by a key carries "Model calls paid by your Anthropic key; the demo paid only for the warehouse.", and the request adds "Your own key paid about $… for model calls; the demo's own-key warehouse limit paid $…."; a failing key's panel shows its fixed failure text as the error. "Forget my key" (shown while a key is kept) wipes the key object, the pending slot and the widgets; the next run says "Your key was forgotten…". The notice says the key is sent to the Streamlit server for this session only, is not stored, is never logged, traced or cached, that the visitor pays their provider directly, and that the models and effort stay the benchmark's. Live mode stays off on the synthetic cache exactly as before (no form, no key field).

- **Saved answers by default (OWNER D-58, D-59, D-60, D-65; DEM-10..DEM-12).** `main` reads `live_switch(env)` once: the live backends (`ask.live_backends`) and the request link (`ask.contact_url`); a setting problem is shown with `st.error` (setting name and fault only) and fails safe (every backend off, or the default link). Near the top, before the banner, `saved_notice` says the answers are saved answers from the benchmark run and that live querying on Snowflake and ClickHouse is switched off to save compute, with "[Ask the owner to turn live compute on](url)" (wording for none, some or all live). Every replay panel shows `saved_panel_note` ("Saved answer from the benchmark run.", plus the engine's switched-off line and link when its backend is not live). Live mode always shows the passcode box and one key field per provider of the page's agent panels (from `run.yaml` when live, else the replay config). With no backend live nothing is built (no `live_settings`, `live_problem`, `shared_live`, guard, store, executor or services) and the page shows `LIVE_SWITCHED_OFF`; on submit a wrong passcode says "Wrong passcode." and a valid visitor or owner passcode (constant-time `passcode_kind`) shows "Live compute is off for … [request link]" and one off column per backend; typed keys are dropped (`KEYS_NOT_USED`). With some backends live, `live_settings(live=)` builds `run.yaml`'s config for those only, the guard path runs unchanged (visitor, owner D-53, own keys D-56) on them with `run_live(live=)`, ClickHouse is warmed only if an agent panel is live, and each off backend gets a "Live compute is off" column. The synthetic cache keeps live off whatever the setting. p95 refuses before any ask unless every measured backend is in `DEMO_LIVE_BACKENDS` (both modes), and page mode treats the page's "Live compute is off" as a refusal (exit 3); nothing shown before the click contains that marker.
- **Own app (D-57, D-65; DEM-13, DEM-14).** Streamlit Community Cloud runs `demo/app.py` from a checkout (it inserts `<repo>/src` into `sys.path` as EvalKit's `demo/app.py` does, then calls `page.main()`), installs `demo/requirements.txt` (D-95: the whole resolved set of the core dependencies and the `demo` extra, as `uv export --extra demo --no-dev --frozen` prints it from `uv.lock`, the EvalKit git pin as in `pyproject.toml`, one TODO for the PyPI switch; `test_deploy` recomputes the set from `uv.lock` and catches planted drift), reads `.streamlit/config.toml` from the repo root (D-96: `client.showErrorDetails = "none"`, so an uncaught exception shows no message or traceback), and reads the Snowflake key from the secret `SNOWFLAKE_RO_PRIVATE_KEY` (PEM text). `scripts/streamlit_secrets.py | pbcopy` writes the secrets TOML from `.env`: `page.SECRETS` with a value (the key text from the file named by `SNOWFLAKE_RO_PRIVATE_KEY_PATH`, as a multi-line string), TOML-escaped, refusing an admin name, never a comment or the local path, and refusing (exit 2) when stdout is a terminal.

The actual deployment and its live page-mode p95: DEM-15, moved to B3.3 by D-93 (proof: a committed `docs/measurements/demo-p95-<date>-page.json`).
