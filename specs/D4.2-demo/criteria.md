# D4.2 acceptance criteria

**DEM-01** With no keys, no `.env` and no `demo/replay.json`, `main(st)` renders the bundled synthetic cache: the sample select box lists the cache's complete samples at index 0, two columns render the first sample's panels (Claude + ClickHouse MCP, Snowflake Cortex Analyst) with SQL and a chart each, and opening makes no call (the page shows every sample through `opening`, in replay, with a passcode set and every backend live, building, warming and asking nothing); the committed `demo/replay.json` is real (not synthetic, every sample answered on both backends with SQL and no error) and the repo's `run.yaml` agrees with it; a real `demo/replay.json` (or `AA_DEMO_CACHE`) is used instead of the example when present. The page module imports without Streamlit (checked in a fresh interpreter, and no top-level streamlit import), and `app.py` is only the import of `main` and its call.

**DEM-02** `panel_view` gives the title with the model, SQL, the answer, the chart as plain JSON with the Vega-Lite schema, "Data as of <date>" (D-50) on every panel, a "Cost $… · … s" line ("Synthetic cost $… · synthetic latency … s" for synthetic panels) and the trace (`[Trace](url)` when the answer has one, otherwise the reason); a panel without a chart shows its rows with `st.dataframe` (never `st.table`) and "First n of N rows"; timed-out and errored panels state why; every Cortex panel carries the honest Cortex line; model text is escaped so it cannot become a link or HTML: markup planted in an answer, a clarification, a suggestion, an executed cell and a column header reaches no Markdown-rendering call raw, through `render_panel` and through `main()`, and every shown string passes the trace `Redactor` (a key that reached a panel is shown redacted).

**DEM-03** Live mode with the passcode asks both backends through the guard (one reservation) and renders two panels, the budget line ("Today's live budget left: $3.00 of $3.00 (local counter), shared by all visitors and the real limit · each request holds at most $1.00 · 5 live questions per hour per session"), the request's cost line and the untraced note; a wrong passcode shows "Wrong passcode." with no call, reservation or warm-up; ClickHouse is warmed (in the background) only after the passcode passes, once per session however often the page reruns, never on merely opening live mode and never in replay; live mode is refused on the synthetic example, without a readable `run.yaml`, and when `run.yaml` differs from the replay answers in as-of date, models, effort or fix_hash (the warning names the field), and its services are built from `run.yaml`'s config, never the cache's; without secrets live mode shows only the not-configured warning; a store that cannot be read shows "unavailable"; a failure building live services is logged by type only (a password in its message never reaches the log) and retried on the next run.

**DEM-04** The banner shows the licence credit beginning "Contains HM Land Registry data © Crown copyright" and exactly "Cortex Analyst returns SQL; its answer text here is a template over the rows it returned.", with the SYNTHETIC label first only when the cache is synthetic.

**DEM-05** The deployment notes (module docstring) name the host secret store, the `pip install agentic-analytics[demo]` extra and the runtime-only secrets (`SECRETS` holds no `*_ADMIN_*` variable); `secret_env` lets the host store override the environment and ignores non-string values; `measure_p95` over 20 asks reports nearest-rank p50/p95/max, timed-out and errored panels and the spend, and passes only with at least 20 asks, p95 under 30 s and no timed-out or errored panel; the p95 script refuses to start when 20 holds exceed `--max-cost` (default $15, at most $25), stops at the cap, times page asks from submit (a stand-in Playwright: page load and typing excluded), stops on a compute-off page, needs an https `--url` in page mode, and records mode (deployed page = DEM-15, in-process = diagnostic), URL or host, backends, models, as-of date, commit and n. The deployed page's live p95 is DEM-15 (B3.3, D-93): `test_live.py` runs it only with `AA_LIVE=1` and an https `AA_DEMO_URL`, page mode only, and checks the record.

**DEM-06** Own key after the passcode (OWNER D-56): a key typed with a wrong passcode is not kept (no `VisitorKeys`, pending slot gone, field emptied) and builds no agent, makes no call and holds nothing; with the visitor passcode it is kept for the session, its panel runs on it (nothing on the $3/day, one own-key hold) and a later ask reuses it; the owner passcode never passes a key to `run_live` (`visitor_keys=None`), neither typed nor stored, and says so; a malformed key or the deployment's own key is refused with its reason before any call; one password field per provider serving a live agent panel (Anthropic only for the default Claude + Cortex page, both when GPT is live, none without an own-key limit); both keys pay for their own panels; per-request clients, `max_retries=0`, fixed models and effort and the offline checks are D4.1's (`tests/demo/test_keys.py`).

**DEM-07** Own-key spend: the keyed panel's model calls are held nowhere and its warehouse part plus the Cortex bound are held on the own-key limit ($5/day, `agentic-analytics-byok`, rate limit 5 per session per hour), unkeyed agent panels on the $3/day; a failing key fails its panel with a fixed, secret-free message shown as the panel's error, and the deployment's agent is never called (D4.1 tests cover each failure kind and the counters).

**DEM-08** A planted key, quoted in full by the provider's error, reaches no log record at any level, no tracer send, no failure-trace export, no file under the working folder (spend counters, ledger, caches), not the page's text, the session state's repr or the `LiveResult`/panel JSON a replay cache would store; a panel text that quotes the key is shown as `[REDACTED:VISITOR_ANTHROPIC_KEY…]` (the session's redactor, not the generic pattern); `Redactor.with_secrets` adds values without changing the original; "Forget my key" wipes the key (its `reveal()` then raises), empties the fields, says so on the next run and the next ask uses the $3/day.

**DEM-09** The notice says the key is sent to the Streamlit server for this session only, is not stored, that the visitor pays the provider directly, and that models and effort stay the benchmark's; the own-key budget line shows $5.00 of $5.00; the page's only choice is the mode (no model picker); live mode on the synthetic cache shows only the synthetic warning even with a key in the session; an owner ask with own keys on reads the same to p95 page mode (owner marker, cost line, two ok panels), the passcode, question and ask-button selectors stay unique, no new text matches a done marker, error text, cost line or timeout text, and the owner and p95 caps ($15, $25) and counter keys are unchanged.

**DEM-10** `DEMO_LIVE_BACKENDS` missing, empty or blank means no backend is live; named backends (case and blanks ignored) and `all` turn exactly those on; an unknown name (`cortex`, `claude_mcp,bogus`, `all,clickhouse`, `yes`, `true`) is a `DemoSettingError` and on the page an error beginning "DEMO_LIVE_BACKENDS names an unknown backend ('cortex')" with every backend off and nothing built; `DEMO_CONTACT_URL` defaults to `https://github.com/biplob819/agentic-analytics/issues`, a mailto link is reported (setting name only, the address never shown) and the default link used, a valid https link replaces it; `run_live(live=)` refuses a backend that is not live with no call or reservation.

**DEM-11** With the setting missing the page builds and connects nothing (tripwires on `build_live`, `shared_live`, `live_settings`, `live_problem`, every guard and store builder, `context_from_env`, `services_from_env`, `executors_from_env`, `warm_up`, `ask_panels`, `run_live` never fire), the first info line says "saved answer from the benchmark run", "switched off to save compute", "Snowflake and ClickHouse" and carries the request link, both panels render their saved SQL and each carries its saved-answer note with its engine and the link; with every backend live the replay panels still say "Saved answer from the benchmark run."; with only Cortex live the real `build_live` needs no Anthropic or ClickHouse variable (its services have no agent), with every backend live the same environment stops the build, and `live_settings(live=())` says live compute is off.

**DEM-12** The passcode box and the key field are shown with compute off; a visitor or owner passcode with a typed key then shows "Live compute is off for claude_mcp, cortex_analyst" with the link, one off column per backend, `KEYS_NOT_USED`, no stored key and nothing built; an empty or wrong passcode with a key says "Wrong passcode." with compute off and with compute on (no agent built, no call, nothing reserved on any counter); with only `claude_mcp` live a visitor or owner ask builds services for `claude_mcp` only, makes no Cortex request or Snowflake query, warms ClickHouse once, reserves once on the right counter and shows a Cortex off column; with only Cortex live ClickHouse is never warmed or queried; the synthetic cache stays off with every backend live; p95 refuses (exit 3, "p95 needs every measured backend live", nothing asked) in both modes unless every measured backend is live, and no text shown before the click matches a done marker.

**DEM-13** `demo/app.py` defines `ROOT` as the repo, inserts `ROOT / "src"` at the front of `sys.path` before importing `main` from `agentic_analytics.demo.page`, and ends with `main()`; run from the checkout with a stand-in `streamlit` it renders the page (two panels, the saved-answers notice first); `demo/requirements.txt` lists exactly the resolved set of the core dependencies and the `demo` extra in `uv.lock` (transitive packages included, `psycopg-binary` for the extra), each pinned `==` to its locked version, `evalkit-harness` exactly as `pyproject.toml` has it, one TODO naming the PyPI switch, and the same lines as `uv export` (when uv is on the PATH); the check catches a missing direct or transitive package, a version drift, an unpinned line, a lost extra's package, a different git commit, an extra package, a duplicate and a new core dependency; `.streamlit/config.toml` sets `client.showErrorDetails = "none"` and holds settings only; the Snowflake key text criteria of D4.1's D-57 paragraph hold.

**DEM-14** From a `.env` with a fake value for every page secret, the admin variables, an owner comment, a blank `OPENAI_API_KEY` and `SNOWFLAKE_RO_PRIVATE_KEY_PATH` naming a generated key file, the script's stdout parses with `tomllib` to exactly `page.SECRETS` (the key as the file's text byte for byte, values with quotes, backslashes and tabs intact) and holds no admin value, comment, path or `_PATH` name; stderr names variables only; with a terminal as stdout it exits 2, writes nothing to stdout and says to pipe to `pbcopy`; an admin name in the list is refused; values with quotes, backslashes, tabs, control characters, non-ASCII, `"""`, a trailing backslash and CRLF round-trip as basic and multi-line strings; a missing or non-PEM key file exits 1 naming the variable, never the path or the content.
