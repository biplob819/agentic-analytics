# Q2.2 acceptance criteria

**GLD-01** `run_gold_check` runs every answer-expected question's gold SQL, with `'{as_of}'` bound to the given as-of date (never sent unbound), on each configured engine through the executors with `row_cap=200`; clarify-expected questions are not executed; an execution error, more than 200 rows, no rows when `expects_empty` is false, or rows when it is true each fail the question; no configured engine is a config error (exit 2). *Proof:* `tests/gold_check/test_run_and_compare.py` (`test_clean_world_passes_and_runs_every_answer_question_on_both_engines`, `test_as_of_is_bound_before_execution`, `test_ambiguous_questions_are_not_executed`, `test_error_truncation_and_empty_results_fail`, `test_expects_empty_inverts_the_empty_rule`, `test_no_engine_is_a_config_error`); live `tests/gold_check/test_live_gold.py::test_live_gold_check_passes_on_the_configured_engines`.

**GLD-02** With both engines, the Snowflake result must match the ClickHouse result under S2.1's column mapping (names case-insensitive, any order) at the question's tolerance (only `Tolerance.columns` covered; a median 0.4% off passes, 0.6% fails, a count off by 0.5 fails), with order checked only for `ordered` questions and equal column counts; a planted mismatch fails the check with `status: "fail"` and exit 1 (`agentic-analytics gold` exits 1 and lists it); single-engine mode skips the comparison, never queries the other engine and is stamped `single_engine`. *Proof:* `test_planted_cross_engine_mismatch_blocks`, `test_tolerance_covers_only_the_named_columns`, `test_column_mapping_by_name_ignores_case_and_order_but_not_extra_columns`, `test_order_matters_only_for_ordered_questions`, `test_single_engine_mode_skips_the_comparison_and_is_stamped`, `tests/gold_check/test_cli_gold.py::test_gold_mismatch_exits_1_and_lists_failures`.

**GLD-03** For a top-N question, `rewrite_limit` changes only the outermost `LIMIT n` literal to `n+1` (subquery limits, comments and every other byte kept; a missing or different LIMIT is refused) and the widened query runs on the determinism engine; the ranking value is the output column of the first ORDER BY key; rows n and n+1 must differ beyond the question's tolerance for the ranking column when covered (a median 0.29% apart at the cut is a tie, 1.4% is not; an uncovered column compares exactly), and for an ordered question every adjacent pair inside the top n must be separated the same way ("ambiguous order inside the top n"), while an unordered top-N only needs the cut; a planted exact tie fails, fewer than n+1 rows pass, a failed tie query fails; all 20 shipped top-N questions rewrite and resolve their ranking column on both engines (`@pytest.mark.gold`). *Proof:* `tests/gold_check/test_ties_and_determinism.py` (`test_rewrite_changes_only_the_outermost_limit_literal`, `test_rewrite_refuses_a_missing_or_different_limit`, `test_ranking_index_is_the_first_order_by_key`, `test_every_shipped_top_n_question_can_be_tie_checked_on_both_engines`, `test_planted_tie_at_the_cut_fails`, `test_values_at_the_cut_within_tolerance_are_a_tie`, `test_ordered_top_n_needs_separated_neighbours_inside_the_list`, `test_uncovered_ranking_column_is_compared_exactly`, `test_distinct_values_at_the_cut_pass`, `test_fewer_than_n_plus_one_rows_cannot_tie`).

**GLD-04** Q2.1's writing-rule lint (exact functions included) runs over the bank and any issue fails its question (a planted `median()` fails with `lint approximate_function`); the ClickHouse gold runs twice and Snowflake once, and a planted non-deterministic result or a failed second run fails; row order counts only for `ordered` questions (a reordered second run fails an ordered question and passes its unordered copy) and column names must be identical. *Proof:* `test_exact_function_lint_fails_the_question`, `test_determinism_respects_ordered`, `test_clickhouse_runs_twice_and_snowflake_once`, `test_planted_non_deterministic_result_fails`, `test_row_order_counts_only_for_ordered_questions`, `test_second_run_failure_fails`.

**GLD-05** From the passing questions, `select_questions` keeps each category's `pack.yaml` quota, drawn with a fixed seed, sorted; the bundled quotas give exactly 100 as 17/17/17/17/16/16; the selection is reproducible, independent of input order and changes with the seed; failing questions are never selected and a category short of its quota is a failure. *Proof:* `tests/gold_check/test_select_and_stamp.py` (`test_bundled_quotas_select_100_as_17_17_17_17_16_16`, `test_selection_is_seeded_and_independent_of_input_order`, `test_selection_draws_only_from_passing_questions_and_reports_short_categories`).

**GLD-06** A run records its `as_of` and writes `gold/<engine>/<qid>.json` (`GoldResult`, `sql_hash` = sha256 of the executed SQL) for every clean gold query, `gold/check-<ts>.json` and `gold/gold_check.json` with identical content in R3.1's `GoldCheck` format, `gold/<engine>/<probe id>.json` (`ProbeGold`) for every probe with gold on the engines its backends use (p-id01, MCP-only, on ClickHouse only), and `gold_check_id` = R3.1's `compute_gold_check_id(selected questions, their gold, snapshot sha256, as_of=, probes=)` over the SELECTED questions only (it differs from the id over all questions, and editing an unselected question keeps the check valid); `run.gold.require_gold` (committed with this node, D-73) accepts a passing check (and its single-engine form only for that engine) and refuses a failed or missing one, one for another pack, snapshot or as-of, one whose selected questions, gold files or probe gold changed after the check, a missing gold or probe gold file, a gold file holding another item, an unknown selected question and an engine the check does not cover; `current_snapshot` takes the newest snapshot record; the runner's own use of these (exit 1 on a different `as_of`, probes scored against their stored gold) is R3.1's; reruns give the same id; `--only` checks one question and writes nothing; `agentic-analytics gold` runs the check (0 pass, 1 fail, 2 config or runtime error, `--json`), takes the as-of date from `--as-of` or `run.yaml`, refuses without a snapshot record (exit 1), and `--verify` validates an existing check without SQL (exit 1 when a file changed after it). The dual-authorship helper sends GPT Sol only the question text, the DDL and the agents' as-of line (with the "last year" definition) with no tools, and `compare_dual` reports agreement at the question's tolerance (fake model; the real call is live). *Proof:* `test_files_are_written_and_r31_accepts_them`, `test_gold_check_id_is_sha256_over_questions_gold_and_snapshot`, `test_editing_an_unselected_question_keeps_the_check_valid`, `test_run_with_another_as_of_is_refused`, `test_probe_gold_is_run_and_checked`, `tests/gold_check/test_require_gold.py` (every refusal above, the record invariants and the newest snapshot), `test_a_failed_check_is_written_as_fail_and_refused_by_r31`, `test_only_checks_one_question_and_writes_nothing`, `tests/gold_check/test_cli_gold.py`, `tests/gold_check/test_dual.py`; gate `tests/gold_check/test_live_gold.py::test_bundled_gold_check_is_clean_when_present` (the bundled check must exist, be clean and, in a checkout, be for the current snapshot record).
