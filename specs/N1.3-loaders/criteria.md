# N1.3 acceptance criteria

**LOD-01** `load_clickhouse(pack, client, force=False)` sends, on an injected admin client, exactly the statements of the pack's `load/clickhouse.sql` rendered with the pack's ClickHouse database: `CREATE DATABASE` and `CREATE TABLE` with `IF NOT EXISTS` added, then the documented `INSERT … SELECT FROM url(…) SETTINGS max_http_get_redirects=10`; the rendered file equals ClickHouse's documented statement (a verbatim copy in the test) apart from layout and the database name, and a one-character change is detected; a second run sends no `INSERT` and reports `skipped`; `force` on a loaded table sends `TRUNCATE TABLE` then the `INSERT` and reports `reloaded` with no duplicated rows; an insert that leaves the table empty raises `LoaderError`; an existing table whose columns differ is refused with the column named, and with `force` dropped, recreated and reloaded; a statement outside the allow-list (`DROP`, an `INSERT` into another database, a `CREATE TABLE` elsewhere, a bare `SELECT … url()`) or a body reaching outside (`INSERT … SELECT FROM remote(…)` or `s3(…)`, a second or non-http `url()`, `ENGINE = URL/S3/MySQL/PostgreSQL/File/Remote/Memory`, `AS SELECT`, `dictGet` defaults, extra `SETTINGS`) added to the pack file is refused before anything is sent, while function names inside string literals are data; a database name that is not a plain identifier raises. *Offline proof:* `tests/load/test_clickhouse_loader.py`, `tests/packs/test_uk_price_paid.py` on a stateful fake that refuses a second plain `CREATE`. *Live proof:* `test_live_load_both_engines_parity_and_as_of`, more than 27 M rows.

**LOD-02** `load_snowflake(pack, conn, workdir=…, download=…)` always runs setup, replacing the file format, internal stage and raw table (`CREATE OR REPLACE`) and refusing an existing typed table whose `DESCRIBE TABLE` columns differ unless `force` (drop and recreate); when every pack table already has rows and `force` is off it reports `skipped` and does not download; otherwise it downloads the URL that the pack's ClickHouse SQL reads (exactly one `url('…')`), records the sha256 of the bytes as downloaded, the size and the line count, writes a byte-for-byte deterministic gzip copy, refuses a download more than an hour from a given `clickhouse_loaded_at` (D-11) before staging it, then sends `PUT 'file://<gz>' @<stage> AUTO_COMPRESS = FALSE OVERWRITE = TRUE`, `COPY INTO <raw> FROM @<stage>/<gz name> … ON_ERROR = ABORT_STATEMENT FORCE = TRUE`, truncate typed, `INSERT … SELECT FROM <raw>`, in that order; raw and typed row counts must agree or it raises; the result carries the snapshot record. The typed table is built from the same transform spec as ClickHouse: both renderings give the same 14 output columns in the same order (checked by parsing both with sqlglot), the raw table is the 16 VARCHAR columns of the ClickHouse `url()` structure, type and duration map to the same lowercase strings, `is_new` is `NUMBER(1, 0)`, dates come from `TRY_TO_DATE` on the first 10 characters, postcodes split on a space, empty fields stay empty strings (`NULL_IF = ()` and `EMPTY_FIELD_AS_NULL = FALSE` pinned by a test); the pack's two SQL files equal the spec's renderings. Local paths that could break the `PUT` literal, a stage file name with a slash, a Snowflake database that is not `DATABASE.SCHEMA`, smuggled statements and bodies reaching outside (external stages with `URL`/`STORAGE_INTEGRATION`/`CREDENTIALS`, `@stage` reads in a SELECT, `TABLE(INFER_SCHEMA(…))`, schema-qualified or AI functions, an INSERT from a table other than the raw table, `AS SELECT` or options after a column list) are refused before anything is sent; only `http(s)` URLs with a host are downloaded; an empty or missing download raises. *Offline proof:* `tests/load/test_snowflake_loader.py`, `tests/load/test_snapshot.py`, `tests/packs/test_uk_price_paid.py`, with a 30-line hand-written CSV in the Land Registry format through a fake whose `PUT` reads the file, `COPY` parses the gzip with the csv module and `INSERT` applies the Python reference of the spec. *Live proof:* `test_live_load_both_engines_parity_and_as_of` (fresh download within the hour of the ClickHouse load).

**LOD-03** `run_parity(pack, runners, snapshot_sha256=…, out_dir=…)` runs every fingerprint of the pack's `parity.yaml` (row count, `sum(price)`, counts by type, duration and `is_new`, min and max date as text, distinct towns, per-year counts, and per text column distinct values, total characters, empty strings and NULLs) on every engine given; every rendered query passes the read-only guard and both engines' queries name the same output columns; results compare exactly (casefolded column names identical, `sql_match` with zero tolerances), so a sum that differs by 1 at benchmark scale fails; the status is `pass`, `fail` (any mismatch or failed query, with the error recorded) or `single_engine` (one runner: nothing compared, not blocking); `require_parity` raises `ParityError` on `fail`; the report, holding both engines' rows and the snapshot sha256, is written to `<out_dir>/parity-<date>.json`; a planted transform difference in each of `is_new`, price, type, duration, date and town fails exactly its fingerprint(s), a district/county swap fails exactly `text_district` and `text_county`, a change to any of the nine text columns fails its `text_` fingerprint, and a Snowflake file format with `NULL_IF = ('')` fails parity; invalid specs (a write, `url()`, a missing engine query, duplicate names, an unknown engine key, no fingerprints) raise `ParityError`. *Offline proof:* `tests/load/test_parity.py` on fakes loaded from the fixture by both loaders. *Live proof:* `test_live_load_both_engines_parity_and_as_of` writes `docs/measurements/parity-<date>.json` with status `pass`, stamped with the sha256 of that run's download.

**LOD-04** `load_probes_clickhouse` and `load_probes_snowflake` replace (`CREATE OR REPLACE TABLE`) `uk_probes.listing_notes` and `ANALYTICS.UK_PROBES.LISTING_NOTES`, in the databases the N1.2 role SQL grants, and insert 10 rows (only `INSERT … VALUES` allowed); reruns leave 10 rows; both engines hold identical rows; markers are `INJ-01` … `INJ-10`, unique, and each note contains its own marker and no other; the probes statements never touch the benchmark table. *Offline proof:* `tests/load/test_probes_loader.py`, `tests/packs/test_uk_price_paid.py`. *Live proof:* `test_live_probes_on_both_engines`.

**LOD-05** `DATA_CARD.md` states, without present-tense claims about what later nodes will enforce (EK L-16), the source (page and CSV URL), the OGL v3.0 licence and the exact attribution from `pack.yaml`, with the date the N1.3 live run checked it word for word on gov.uk, the snapshot sha256, download time, row count, `max_date`, as-of date and parity report as recorded by the N1.3 live run and equal to the newest snapshot record and its passing parity report in `docs/measurements/` (the as-of date equal to `last_complete_month(max_date)`, no placeholder left), the as-of rule with examples, the registration-lag caveat, the transforms of every column on both engines, the enum-order note, and the probes table with every marker. *Offline proof:* `tests/load/test_data_card.py` (reads the committed records). *Live step:* the 2026-11-16 live run filled in the snapshot facts.

**LOD-06** `last_complete_month(max_date)` returns the last day of the month before `max_date`'s month, always (D-50: 2026-10-31 and 2026-10-30 both give 2026-09-30; a hypothesis property: a month end, in the previous month, the same for every day of a month); `as_of_for` honours `as_of_rule: fixed` and refuses an as-of date after `downloaded_on`; `max_date_from_parity` takes `max_date` from the `date_range` fingerprint, refusing a failed report, disagreeing engines or a non-text date; `write_as_of` sets `as_of` in a run-config YAML that `load_run_config` then accepts with its other keys kept. On the fixture (latest sale 2026-10-14) the as-of date is 2026-09-30. *Offline proof:* `tests/load/test_asof.py`. *Live proof:* `test_live_load_both_engines_parity_and_as_of`.

**LOD-07** The bundled pack ships in the wheel (every data file readable through `importlib.resources`; `uv build` lists them) and loads by name; a directory loads by `Path` or a string with a path separator; a bare name never falls back to a directory; manifests are validated as `DatasetPack` (schema 1.0) with duplicate keys, bad YAML and non-mappings refused and the file named; a bundled pack must be named as its directory; `pack_file` refuses paths that leave the pack (absolute, `..`, `.`, empty segments, backslashes, NUL, symlinks out of a directory pack) and names missing files; loaders read only the pack, so a copied pack with another database name loads there. *Offline proof:* `tests/packs/test_packs.py`, `tests/load/test_clickhouse_loader.py›"test_loader_reads_only_the_pack"`.
