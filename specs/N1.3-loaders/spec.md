# N1.3 — Loaders, parity and data card

**Wave 1. Depends on:** N1.2. **Unblocks:** N1.4, Q2.1, Q2.2.

## Goal
Both engines hold the same UK price paid snapshot, loaded only from the dataset pack's fixed SQL, proven equal by exact fingerprints, with a planted probes table, a stated as-of date and a data card. This half is the offline build: everything runs on fakes; the measurement (both real loads, parity, as-of) is the live half, which needs the trial accounts.

## Design decisions
- **Loaders write, so they cannot use the read-only guard.** Instead every statement comes from the pack's SQL files, is rendered with validated identifiers (`warehouse.roles._ident`; Snowflake `DATABASE.SCHEMA` as two of them; local file paths limited to characters that are safe inside a quoted literal), split quote- and comment-aware, and classified against a per-loader allow-list of shapes *and* objects (for example: `INSERT` only into the pack's tables in the pack's database; `PUT` only of this load's snapshot file to the pack's stage, and `COPY` only of that file). Statement **bodies** are checked too, with literals masked so data is never read as code (and no backslash, block or `#` comment, backtick or double-quoted function name, which the engines read differently from the masker; verifier): no external table function or engine anywhere (the read-only guard's deny lists: `url`, `remote*`, `s3*`, `mysql`, `postgresql`, `file`, `dict*`, Snowflake `INFER_SCHEMA`, `TABLE(…)`, AI functions, ...), no schema-qualified calls, no `@` stage reference outside `PUT`/`COPY`; ClickHouse tables only with a MergeTree engine and no `AS`, `SETTINGS` or `TTL` (a web or S3 disk reaches outside); Snowflake tables with nothing after the column list; stages internal (`FILE_FORMAT` only). An `INSERT … SELECT` must be one SELECT from one source: on ClickHouse exactly `url('http(s)://…', '<format>', '<structure>')` with at most `SETTINGS max_http_get_redirects`, on Snowflake the pack's raw table; probes allow only `INSERT … VALUES`. Anything else stops the load before a single statement is sent. Loaders take an injected **admin** client or connection and never import the read-only executors (a test reads their imports). Parity queries are reads, so they must also pass the read-only guard even on an admin connection.
- **One transform spec.** `transforms.py` lists each typed column once (name, op, raw field, ClickHouse type, Snowflake type). Three renderers read it: ClickHouse SQL, Snowflake SQL and a Python reference used only by tests. The pack's SQL files are the renderings (a test checks byte equality), loaders read only the files, and the ClickHouse rendering equals the documented statement from ClickHouse's docs apart from layout and the database name (a test against a verbatim copy of the docs). Snowflake: `TO_NUMBER(price_string, 10, 0)`, `TRY_TO_DATE(LEFT(time, 10), 'YYYY-MM-DD')`, `SPLIT_PART(postcode, ' ', n)`, `CASE` mapping type and duration to the same lowercase strings (unmapped codes pass through on both engines, as ClickHouse's three-argument `transform` does), `IFF(b = 'Y', 1, 0)` into `NUMBER(1, 0)`. Empty fields stay empty strings (`EMPTY_FIELD_AS_NULL = FALSE`, `NULL_IF = ()`), as in ClickHouse's `String`.
- **ClickHouse idempotence without editing the documented SQL.** The file keeps the documented `CREATE DATABASE` / `CREATE TABLE`; the loader adds `IF NOT EXISTS` when sending, then reads `DESCRIBE TABLE` and compares it with the pack's columns (names exact, types whitespace-free with `Enum8` items sorted). A difference is refused with the column named, unless `force`, which sends `DROP TABLE` and recreates it. Each `INSERT` is skipped when its table has rows; `force` sends `TRUNCATE TABLE` first. An insert that leaves the table empty stops the load.
- **Snowflake load.** Setup always runs: database and schema `IF NOT EXISTS`; file format, internal stage and raw table of 16 VARCHARs `CREATE OR REPLACE`, so no stale object survives; typed table `IF NOT EXISTS`, then the same `DESCRIBE TABLE` comparison as ClickHouse (names case-insensitive; `VARCHAR` = `VARCHAR(16777216)`, `NUMBER(10, 0)` = `NUMBER(10,0)`), refused on a difference unless `force` (drop and recreate). If the typed table has rows and `force` is off, nothing is downloaded. Otherwise: download (injectable) → sha256 of the bytes as downloaded → gzip with `mtime=0` and no file name (byte-for-byte deterministic) → (with `clickhouse_loaded_at`, refuse a download more than an hour from the ClickHouse load, D-11) → `PUT … AUTO_COMPRESS = FALSE OVERWRITE = TRUE` → `COPY … ON_ERROR = ABORT_STATEMENT FORCE = TRUE` → truncate typed → `INSERT … SELECT`. Raw and typed counts must agree. The download URL is read from the pack's ClickHouse SQL (`url('…')`, exactly one), so both engines load the same source (D-11).
- **Parity.** `parity.yaml` has one query per engine for each fingerprint (row count, `sum(price)`, counts by type, duration and `is_new`, min and max date, distinct towns, per-year counts, and `text_<column>` for each of the nine text columns: distinct values, total characters, empty strings and NULLs, so a swapped, truncated or NULL-for-empty column fails), written so both engines return the same column names and value types: enums cast to text on ClickHouse, dates returned as `YYYY-MM-DD` text on both. Comparison: casefolded column names identical, then EvalKit's `sql_match` with `rel_tol = 0, abs_tol = 0` (unordered unless `ordered: true`). Status `pass`, `fail` (any mismatch or failed query; `require_parity` raises) or `single_engine` (one runner: recorded, not compared, not blocking, D-29). The report, with the snapshot sha256, goes to `docs/measurements/parity-<date>.json`.
- **As-of rule (D-50).** With `max_date` the latest sale date (from the parity `date_range` fingerprint, which both engines agreed on): the as-of date is the last day of the month before `max_date`'s month, always, because the newest month is partly registered whatever day it ends on. With `downloaded_on`, an as-of date after the download date is refused. `as_of_rule: fixed` uses the pack's date under the same check. `write_as_of` sets `as_of` in a run-config YAML (other keys kept, comments not).
- **Probes.** `<database>_probes.listing_notes` on ClickHouse and `<DATABASE>.<SCHEMA>_PROBES.LISTING_NOTES` on Snowflake, the names the N1.2 role SQL already grants. 10 rows `(note_id, postcode1, town, note)`; each note carries instruction text containing its own marker `INJ-01`…`INJ-10` and no other (no separate marker column, D-51). `CREATE OR REPLACE TABLE`, then insert: idempotent, and no stale schema survives. Which probes use which rows is Q2.1's.
- **Pack discovery.** A bare name means a bundled pack only (no fallback to a same-named directory, so `--pack` cannot be hijacked by the working directory); anything with a path separator, a leading `.` or `~`, or a `Path` is a directory. Manifests load through the duplicate-key-refusing YAML loader. `pack_file` refuses empty, absolute, `..`, `.`, backslash and NUL paths, and on directory packs any symlink that resolves outside the pack.

## Offline vs live
Offline (this half, green on fakes): every criterion's logic. Live (the N1.3 measurement, needs both trial accounts): the real ClickHouse `url()` load, the real Snowflake download/PUT/COPY, real parity and its report under `docs/measurements/`, the snapshot sha256 and as-of date written into `DATA_CARD.md`, and the probes on both accounts. `tests/load/test_live.py` holds those runs, skipped unless `AA_LIVE=1` (the two full loads also need `AA_LIVE_LOAD=1`).

Applying the role SQL to the accounts, the semantic layer (N1.4), probe questions (Q2.1), `pack check` (QST-08).
