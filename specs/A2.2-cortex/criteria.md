# A2.2 acceptance criteria

**CTX-01** `KeyPairJwt` mints an RS256 token whose `sub` is `ACCOUNT.USER` and `iss` is `ACCOUNT.USER.SHA256:<base64 sha256 of the DER public key>`, ACCOUNT being the account identifier before its first dot, upper-cased (locator with region, org-account, `.privatelink` and `.global` forms each tested), while the hostname keeps the full account lower-cased with underscores as hyphens; the token lasts 3,540 s and never more than 3,600 s, is reused until `now >= exp - 300 s` (exactly at the boundary it is minted again) and never after expiry; PEM, DER and encrypted PEM RSA keys load, while unreadable, non-RSA or wrongly decrypted keys, a missing file, or a blank account or user raise `CortexConfigError`. `CortexClient` POSTs to `https://<host>.snowflakecomputing.com/api/v2/cortex/analyst/message` with `Authorization: Bearer <JWT>`, `X-Snowflake-Authorization-Token-Type: KEYPAIR_JWT`, `Content-Type: application/json` and exactly `{"messages":[{"role":"user","content":[{"type":"text","text":q}]}],"semantic_view":"DB.SCHEMA.VIEW"}` under the per-phase timeout and a total deadline that spans retries; a semantic view that is not three identifiers is refused; 408/409/429/5xx and failures before sending (connect, pool, write, proxy) are retried for exactly six attempts with a fresh token per attempt; failures after sending (read errors, dropped connections, mid-body included) and read timeouts are never retried; too many redirects, an unsupported protocol and any other non-200 raise after one request and `classify_error` calls them `config`; no exception message, repr or shown cause carries the token, the key bytes, the passphrase or the key path (each planted and checked).
**CTX-02** `parse_response` reads `request_id`, joined `text` blocks, the first `sql` `statement` with `confidence.verified_query_used`, suggestions from type `suggestions` or `suggestion` (list under either key, blanks and duplicates dropped), `warnings[].message` and `response_metadata.model_names`/`question_category`/`analyst_latency_ms` (finite and non-negative, else None); the recorded live replies (SQL, declines with suggestions, 400/401/404 bodies) parse with nothing ignored; unknown, untyped or empty content and extra `sql` blocks are skipped and named in `ignored`; suggestions beside SQL are dropped and recorded; odd metadata types never crash; a body that is not a JSON object with a `message.content` list raises `CortexSchemaError`, which `ask_cortex` turns into `error="schema"` with `cortex_messages=1`.
**CTX-03** SQL from Cortex is executed exactly once through the injected executor as `execute(sql, row_cap=10_000)` (or the given cap); nothing is executed for suggestions or text; the run carries that `Execution` and its `elapsed_ms`; an Execution from another engine raises `TypeError` and executor exceptions propagate.
**CTX-04** Suggestions without SQL give an answer with the suggestions kept, `sql=None`, `clarification=None`, `error=None` and `asked_for_clarification` true; with SQL present, suggestions are dropped and the answer is not a clarification.
**CTX-05** The answer text is `template_answer(execution)`: `The result is <v>.` for one cell, `COL: v, ...` for one row, `<n> rows returned; first: ...` (n = rows held, `(cut at the row cap)` when truncated) for more, `The query returned no rows.` and `The query failed (<error>).`; cells are written exactly (no separators, no exponent, `NULL`, `true`/`false`), so the template's numbers pass `unsupported_numbers`; Cortex's text is kept as `interpretation` and never enters the answer; a failed execution keeps the SQL with `answer.error` None.
**CTX-06** One request with one user message per question; a text-only or empty reply is `error="refusal"` with the text kept; transport failures outlasting six attempts give `error="transport"` with `cortex_messages=0`, a reply lost after sending `error="transport"` with `cortex_messages=1`, a read timeout `error="timeout"` with `cortex_messages=1`, the deadline `error="timeout"` with 1 if a request was in flight and 0 if it fired during backoff, an undecodable 200 `error="schema"` with 1; all with `sql=None`, `answer=""` and nothing executed; unexpected exceptions and config errors propagate; `CortexRun` carries `cortex_messages`, `api_latency_ms` of the API call alone on the injected clock on every path, `warehouse_elapsed_ms`, Cortex's warnings (on the SQL, suggestions and refusal paths) and the parsed response; every answer has backend `cortex_analyst`, no steps, `model_snapshot = ",".join(model_names)` or None and the body's `request_id` (kept on the schema-error path, blank → None); a blank question is refused before any call.
