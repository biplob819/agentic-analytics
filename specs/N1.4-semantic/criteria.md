# N1.4 acceptance criteria

**SEM-01** `packs/uk_price_paid/semantic.yaml` loads through `load_semantic(pack)` into a frozen, strict `SemanticModel` (unknown keys, duplicate YAML keys, non-mappings and a wrong `schema_version` refused, the file named). It has one table (`uk_price_paid`) with a description and synonyms; dimensions `town`, `district`, `county`, `locality`, `street`, `postcode1`, `postcode2`, `type`, `duration`, `is_new`, the time dimension `date` and the derived `year` and `month`; the fact `price`; the metrics `sales_count`, `total_value`, `average_price` and `median_price`; the synonyms "city" (town), "borough" (district; "area" and "house prices" deliberately absent, OWNER D-67), "new build" (is_new), "property type" and "house type" (type), "tenure" (duration); sample values for `type` (all five), `duration` (all three) and a few uppercase towns; and descriptions that state uppercase place names, the enum values, price in GBP, the completion date, data since 1995, the as-of rule in D-50's words ("the last day of the month before the latest month in the data") and the registration lag. Validation refuses: a name used twice (across dimensions, facts and metrics), a synonym used twice or equal to a name, a metric over an undefined fact, no plain time dimension, a transform on a non-time dimension, multi-line or blank text (every character `str.splitlines` splits on, U+2028 and U+0085 included), and duplicate sample values; against the pack's load SQL it refuses a column missing from the table on any engine, a non-numeric fact, a time dimension on a non-date column, a table name that is not the pack's, and engines that disagree on the column list. The owner reviews the file (QST-05 / SEM review sitting). *Offline proof:* `tests/semantic/test_model.py`. *Owner step:* review sitting.

**SEM-02** `semantic_view_ddl(model, view_name, table_fqn)` returns one `CREATE OR REPLACE SEMANTIC VIEW` statement in Snowflake's grammar (TABLES, FACTS, DIMENSIONS, METRICS, view COMMENT) with every item, its expression (`YEAR(…)`, `DATE_TRUNC('MONTH', …)`, `COUNT`/`SUM`/`AVG`/`MEDIAN`), `WITH SYNONYMS = (…)` and `COMMENT = '…'`; single quotes are doubled and backslashes doubled in every literal; view and table names that are not three plain identifiers are refused; the output for the bundled pack equals `tests/semantic/golden/uk_price_paid.sql` and for a fixture with quotes and backslashes equals `tests/semantic/golden/quoting.sql`; the DDL reader recovers every comment and synonym unchanged. *Offline proof:* `tests/semantic/test_snowflake.py`. *Live proof (passed 2026-11-16):* `test_live_semantic_view_created_and_granted` creates the view as SYSADMIN, grants SELECT to `ANALYTICS_RO` (seen in `SHOW GRANTS ON SEMANTIC VIEW`), and `DESCRIBE SEMANTIC VIEW` lists every dimension, fact and metric with exactly the generated comment text and synonyms, and the view comment; `test_live_sample_values_exist_in_the_data` finds every sample value in the loaded table.

**SEM-03** `descriptions_block(model)` is the exact text of the `descriptions` fix: it names every dimension, fact and metric with its column or derivation, its comment text (description plus sample values) and its synonyms, plus the overview and the table; it is byte-identical across calls and across a reload of the YAML, and for the bundled pack equals `tests/semantic/golden/uk_price_paid.prompt.txt`. `semantic_hash(model)` is a 64-hex sha256 of the canonical model that does not change with YAML key order, comments or explicit defaults, and does change when any description, synonym, sample value, name, column or aggregation changes. *Offline proof:* `tests/semantic/test_prompt.py`.

**SEM-04** `semantic_parity(ddl, block)` parses both generated texts (not the model) and returns no issues for the generated pair; it compares comment text, synonym sets and each item's source (the block's Column or Aggregation line against the DDL expression); it reports each planted defect: a column, derivation or aggregation changed on either side, an expression it does not understand, a synonym dropped, added or changed on either side, a comment changed on either side, an item missing from either side, the view or table comment changed, and a generator that skips synonyms or sample values in one output (monkeypatched); `require_semantic_parity` raises `SemanticParityError` naming the item. *Offline proof:* `tests/semantic/test_parity.py`.
