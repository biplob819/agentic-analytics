# D4.1 — `ask()` and guard

**Wave 4 (Should, US7). Depends on:** A2.3 (answer assembly, traces), R3.1 (services, CLI). Also uses N1.2 (executors, SQL guard), N1.5 (MCP toolbox), N1.6 (prices, credit rates), A2.1 (agent loop), A2.2 (Cortex), EvalKit's `evalkit.demo.guard` (pinned, D-2). **Unblocks:** D4.2.

## Goal
Tech Spec §10's `ask(question, backends, mode) -> list[AnalyticsAnswer]` with cost and latency per panel: replay from a demo cache (no calls, works with no keys through a bundled synthetic example) and a live path behind EvalKit's guard and a daily counter under this project's own key (D-17), backends in parallel with a 25 s timeout each, a ClickHouse warm-up, the benchmark's safety layers for free text, and aggregate-only logs. No accounts exist yet: replay is complete; live runs end to end against the committed fakes; the real-account proofs are marked `live` and skip unless `AA_LIVE=1`.

## Decisions
- **API.** `ask()` is synchronous, as §4 writes it; it returns `[p.answer for p in ask_panels(...)]`. A `Panel` adds `cost_usd`, `latency_ms`, `bound_usd`, `timed_out`, `capped`, a 20-row preview of the executed rows and a note. Replay needs `cache`; live needs `ctx` (and, for visitors, `guard`, `passcode`, `session`). `ask` is not re-exported from `agentic_analytics.demo`, so that dotted name always means the module.
- **Default panels.** `claude_mcp` and `cortex_analyst` (US7 "both backends"); any subset of the three backends can be asked.
- **Replay (ASK-02).** One JSON file: config (models, as-of, limits), pack ref, the pack's `fix_hash` and licence credit, backends, and one entry per question with a panel per backend and the `DemoStamp` it was asked under (backends, agent models, effort, as-of date, pack id@version, fix_hash). Loading refuses a cache in which any entry's stamp differs from the stamp of its own top-level config, so the config always describes every answer. A rebuild reuses an entry only under an equal stamp; under another stamp `demo-cache` is refused (exit 2, naming the fields) unless `--redo`, which then re-asks every sample. A synthetic cache always carries a label saying SYNTHETIC (a blank one gets the default; any other is refused). Live mode never takes its config from the cache (D4.2 reads `run.yaml`). Matching collapses whitespace and folds case. Replay never touches `ctx` or the network. `samples()` lists questions answered on every backend without error; the first opens the page. `demo-cache` picks questions round-robin over the six categories by id, asks only questions not already answered on every backend (`--redo` re-asks failed ones), prints an upper bound first (exit 3 over `--max-cost`, default $10: ten two-panel samples hold at most about $7.40), traces samples to Langfuse when configured (sample questions are public), writes atomically, and appends one `demo-cache` spend-ledger line per run that asked anything (Tech Spec §9, as the runner's, D-78: the agent panels' charge as `spent_usd`, the Cortex messages' trial credits under `credits`, never a question).
- **One number (ASK-03, EK L-39).** Per panel, an upper bound: agents `max_turns × (input_tokens_per_turn × highest input price + max_output_tokens × highest output price)` plus ClickHouse compute for the timeout; Cortex one message (`credits_per_message × $/credit`) plus the XS warehouse's 60 s minimum. The request's hold is their sum. The guard checks the hold against the per-request cap ($1.00; a two-panel hold is about $0.74, three panels about $1.50 and are refused), reserves the hold atomically against $3/day, and each agent panel runs capped at its bound's model part. After all panels end, the reservation is settled to the charged total (never above the hold).
- **Enforced bound.** `BudgetedModel` wraps the benchmark's adapter (built with `max_tokens = 2048` per turn). Before each turn it prices the worst case from an upper bound on the prompt (previous billed prompt + its whole output + every byte added since, one token per UTF-8 byte, plus framing and the provider's tool-use preamble) at the highest input price (cache writes and the long-context tier included) and the full output limit at the highest output price; a turn that does not fit is not sent (a zero-cost `max_tokens` stop ends the loop with `step_budget`, `capped=True`). A turn in flight that raises or is cancelled stays charged at its worst case. Live limits: 6 turns, 2,048 output tokens per turn, 1,000 executed rows.
- **Guard (D-17).** EvalKit's `Guard` (constant-time passcode first, before any other check or call; 5 asks per session per hour; per-request cap; atomic daily reservation) and its spend stores, imported from `evalkit.demo.guard`. `EVALKIT_DEMO_DATABASE_URL` set: EvalKit's `PostgresSpend` through `keyed_connect`, which keeps the counter in the schema named `agentic-analytics` of the shared Neon database (every transaction starts with `SET LOCAL search_path`, so EvalKit's own `public.demo_spend` is untouched and nothing leaks through a transaction pooler). Unset: `SqliteSpend` at `.cache/demo-spend-agentic-analytics.sqlite`. Passcode from `DEMO_PASSCODE` (§4); a typed passcode with no UTF-8 form (a lone surrogate) is a wrong passcode, never an encoding error (`check_passcode`).
- **Parallel and timeout (ASK-04).** Each panel runs on its own thread and event loop (the executors and Cortex's execution are synchronous, so one shared loop could not honour a timeout). A panel not finished at 25 s is stopped (no further model turn), its task cancelled, and it reports "Timed out after 25 s; no answer from this backend." An agent's timed-out charge is what it spent plus the in-flight turn's worst case plus ClickHouse for 25 s; a Cortex panel's is its whole bound. The agent loop's own wall clock is 30 s so the panel timeout fires first. Two agent panels share the ClickHouse executor through a lock.
- **Warm-up (H13).** `warm_up(executor)` sends `SELECT 1` (`row_cap=1`) through the read-only executor, under the executor's lock (the page runs it on a background thread beside the panels); at most once per 5 minutes per process, so repeated asks cannot keep the service awake. Failures are reported, never raised. The page calls it only after the passcode check passes.
- **Question text.** `check_question` refuses NUL and every other control character (Cc) except tab, CR and LF, which a text area sends and which are collapsed to one space before the question goes anywhere; Unicode format characters (Cf: bidi overrides and isolates, zero-width characters, BOM, soft hyphen) and lone surrogates; blank or over 500 characters.
- **Free text (ASK-05).** The same `ask_mcp` loop with the N1.2 guard on every `run_select_query` (D-37), the N1.5 toolbox allow-list, and the executors' own guard under the read-only roles; Cortex's SQL goes through the Snowflake executor's guard.
- **Logs.** One JSON line per ask on `agentic_analytics.demo`: `at`, `mode`, `backends`, `latency_ms`, `cost_usd`, `outcome` (`ok`, `timeout`, `refused`, `bad_input`, `error`). Failures log the exception type only; provider messages are never echoed onto a panel (`the provider rejected the API key`, otherwise `failed (<type>)`), and a failed agent panel is still charged what its model was charged (a failed turn at its worst case) plus its whole ClickHouse part for the timeout (its queries may have run; on an own-key ask that part settles on the own-key limit), a failed Cortex panel its whole bound, which is what the reservation settles to.
- **Visitor own keys (OWNER D-56, D-61; the D4.1 side of D4.2's DEM-06..DEM-08).** `ask_panels(..., visitor_keys=, byok_guard=)` needs the visitor guard (the passcode is checked first, before any key is touched), refuses keys with the owner ledger or a trace id, and `run_live(owner=True)` drops them. `keyed_backends` picks the agent panels whose deployment model's provider has a key (`claude-*` Anthropic, `gpt-*` OpenAI). Each ask builds new agents through `visitor_agent` (the benchmark adapter on a new SDK client with `api_key=` and `max_retries=0`, `with_retries` cut to one quick retry; the model, effort and output limit are the deployment's) wrapped in `KeyedModel`, inside `BudgetedModel` as usual, so the visitor's spend per panel is capped at the model bound too. Holds: a keyed panel's ClickHouse part (25 s) and the Cortex panel's whole bound go to `make_byok_guard` (EvalKit's guard, the visitor passcode, $1 per request, `BYOK_DAILY_CAP_USD` $5/day, 5 asks per session per hour, counter `agentic-analytics-byok`, Postgres schema or `.cache/demo-spend-agentic-analytics-byok.sqlite`), reserved first; any unkeyed agent panel's whole bound goes to the $3/day guard, and if that is refused the warehouse hold is settled to 0. Each settles to what its panels charged (an exception before the panels leaves both holds charged). `run_panels(agents=)` takes the keyed agents with no fallback to the deployment's agent. Every exception from a keyed call becomes `VisitorKeyFailed` (rejected, quota, rate-limited, model not available, other; fixed text ending "The demo's own key was not used."), raised outside the handler so nothing is chained; the agent loop treats it as a config error, so the panel fails with that text. `VisitorKey` keeps the value in one slot behind `reveal()`, shows only the provider in `repr`/`str`, refuses pickling and is wiped by `forget()`. `check_key` is offline: prefix, 40 to 256 characters of `[A-Za-z0-9_-]` (outer spaces and line breaks from a paste trimmed), and never the deployment's own key.
- **Saved answers by default (OWNER D-58, D-59, D-60, D-65; the D4.1 side of D4.2's DEM-10..DEM-12).** `live_backends(env)` reads `DEMO_LIVE_BACKENDS` (comma list of `claude_mcp`, `gpt_mcp`, `cortex_analyst`, or `all`; case and blanks ignored; empty or missing = no backend live); any unknown name raises `DemoSettingError` (a reason naming the setting, never its raw value, safe to show on the public page) and the caller treats every backend as off. `contact_url(env)` gives `DEMO_CONTACT_URL` (https, printable ASCII only, a dotted host of valid DNS labels, a valid port, no `@`, whitespace, quotes, brackets or parentheses; default `https://github.com/biplob819/agentic-analytics/issues`) or `DemoSettingError`. `run_live(..., live=)` (a required keyword: no caller can fail open by leaving it out) refuses with `compute_off_text` ("Live compute is off for …") an ask naming a backend not in `live`, owner asks included, before the passcode, a reservation or any call. `demo-cache` (owner tool) ignores the setting.
- **Snowflake key text (D-57, D-65).** `warehouse.snowflake.ro_key_from_env` picks `SNOWFLAKE_RO_PRIVATE_KEY_PATH` when set, else the PEM text `SNOWFLAKE_RO_PRIVATE_KEY` (one-line `\n` escapes turned into line breaks), else None; `SnowflakeExecutor(private_key_text=)`, `KeyPairJwt.from_key_text`, `services_from_env` and `doctor.executors_from_env` accept either. Failures on the text name the variable and the exception type with no chained cause; the text is in no repr, and `tracing.SECRET_ENV_NAMES` redacts it.
- **Tracing.** Owner runs (`demo-cache`) send each sample's trace and store the link on the answer. Visitor live asks send no trace: visitor questions are never stored (EK D-54); the panel says so.
