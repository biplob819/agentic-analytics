# D4.1 acceptance criteria

**ASK-01** `ask(question, backends, mode)` returns one `AnalyticsAnswer` per backend, in the order asked, and `ask_panels` the same answers as `Panel`s with `cost_usd`, `latency_ms`, `bound_usd` and the executed-row preview; live panels over the fake world carry SQL, an answer and a Vega-Lite chart, each panel's cost lies in (0, bound], a Cortex panel costs one message ($0.201 at the planning rates) and carries the honest Cortex line; duplicate or missing backends, an unknown mode, a blank question, a question over 500 characters (the limit is 500, checked with a literal 501-character question) and live mode without services are errors.

**ASK-02** `agentic-analytics demo-cache --questions 10` picks ten questions round-robin over the six categories, prints an upper bound first (`--dry-run` stops there; a bound over `--max-cost` exits 3 with nothing asked or written), writes `demo/replay.json` atomically with the run's config, pack and licence credit, and on a rerun asks nothing already answered on every backend under the same stamp (`--redo` re-asks only entries with a failed panel); a rerun under a different as-of date, model, effort, pack version or fix_hash asks nothing and exits 2 naming the field unless `--redo`, which re-asks every sample and stamps them with the new config; a cache whose entries' stamps differ from its config is refused at load; configuration problems exit 2 with no call. Replay returns the stored panels with no call of any kind (call counter zero, sockets blocked), matches questions across whitespace and case, and raises `KeyError` for an unknown question or backend. A synthetic cache with a blank label gets the default SYNTHETIC label, and one whose label does not say SYNTHETIC is refused. The bundled SYNTHETIC example under `demo/example/` is labelled synthetic, credits HM Land Registry, holds 10 samples on both demo backends and is byte-identical to what `tests/demo/example_data.py` generates.

**ASK-03** The live path uses EvalKit's `Guard` with the D-17 limits ($3 a day, 5 asks per session per hour, $1 per request): a wrong passcode is refused before any call or reservation (even for a bad question), a hold over the per-request cap, a sixth ask in an hour from one session, a used-up day and a store outage are each refused with a safe message and no call; the single hold (sum of the panels' bounds) is what the cap checks, what the store reserves and what the panels are capped at, and the reservation settles to the charged total; 20 concurrent $0.74 reservations against $3 admit exactly 4. `BudgetedModel` refuses a turn whose worst case (bytes as tokens, highest input and output prices, the adapter's output limit if larger) would pass its cap, charges a failed or cancelled turn at its worst case and refuses every turn after `stop()`. The counter is SQLite without `EVALKIT_DEMO_DATABASE_URL` and EvalKit's `PostgresSpend` with it, kept under the schema `agentic-analytics`: a fake Postgres shows this project's counter, EvalKit's `public` counter and a third key never share a total.

**ASK-04** Backends run in parallel (two 0.4 s panels finish in under 0.75 s); a panel past the timeout (25 s by default, 0.5 s in the test) says it timed out while the other still answers, its hung turn never completes, and it is charged within its bound (a timed-out Cortex panel at its whole bound); `warm_up` sends exactly `SELECT 1` with `row_cap=1`, not again within 5 minutes, reports failures without raising, and the statement passes the SQL guard.

**ASK-05** A free-text question's `DROP TABLE` and `url()` queries are refused by the SQL guard before the MCP server sees them (recorded `write_refused` and `guard`), a control-plane tool call never reaches the server, and hostile Cortex SQL is refused by the Snowflake executor's guard; every ask writes one aggregate log line with exactly `at`, `mode`, `backends`, `latency_ms`, `cost_usd`, `outcome`, and a marker in the question, the agent's SQL and its answer reaches no log record at any level and no file; a failing provider's or Cortex's message (which could quote a key) is never shown on a panel or the page, for RuntimeError, ValueError, KeyError, OSError, ConnectionError and TimeoutError alike, and a failed agent panel is charged its failed turn's worst case plus its ClickHouse part for the timeout (never 0), settled as such; `check_question` refuses NUL, other control characters except tab and line breaks, Cf format characters (bidi, zero-width, BOM) and lone surrogates, before any call.

**OWNER D-58..D-60 (D4.1 side; the rows are D4.2's DEM-10, DEM-12)** `live_backends` is empty for a missing, empty or blank setting, gives exactly the named backends (case and blanks ignored) and all three for `all`/`ALL`, and raises `DemoSettingError` ("DEMO_LIVE_BACKENDS names an unknown backend … Live compute stays off") for `cortex`, `claude_mcp,bogus`, `all,clickhouse`, `yes`, `true`; `contact_url` defaults to the GitHub Issues page and refuses http, mailto, an `@` anywhere, `javascript:`, a host without a dot, a space, a Markdown-breaking `)[`, and ftp; `run_live(live=frozenset())` or `live={claude_mcp}` on a two-backend ask is refused ("Live compute is off for … cortex_analyst …") with no call and no reservation, and with every backend live the same ask runs and reserves once.

**D-57 (D4.1 side; the row is D4.2's DEM-13)** With only `SNOWFLAKE_RO_PRIVATE_KEY` set the executor's connection key equals the PEM's DER (also when pasted on one line with `\n` escapes), the path wins when both are set, neither gives no executor, and the Cortex JWT from text has the same issuer as from the file; `services_from_env` builds Cortex from the text and names both variables when neither is set; a malformed planted PEM fails the executor, the JWT and `services_from_env` with messages naming `SNOWFLAKE_RO_PRIVATE_KEY`, no chained cause and no planted text, and no planted text or real key line reaches a repr, the doctor report or a log record.

**OWNER D-56 (D4.1 side; the rows are D4.2's DEM-06, DEM-07, DEM-08)** Keys are refused offline (no socket, no SDK client) for a blank value, inner whitespace, tab, NUL, zero-width or non-ASCII characters, a wrong prefix, an Anthropic key in the OpenAI field, 39 or 257 characters and the deployment's own key, with messages that quote no 8-character run of the key; `VisitorKey`/`VisitorKeys`/`KeyedModel` show no key in repr, str or format and refuse pickling; `sdk_client` builds a new client per call with the visitor key and `max_retries=0` while `ANTHROPIC_API_KEY` holds another key, leaving `os.environ` unchanged. A keyed Claude panel plus Cortex reserves nothing on the $3/day and exactly the ClickHouse 25 s part plus the Cortex bound on the own-key limit, settles to the warehouse charge, and never calls the deployment's agent; with GPT unkeyed, the GPT bound alone is held on the $3/day; a key no panel uses changes nothing. The own-key limit is $5/day under `agentic-analytics-byok` (separate SQLite file and Postgres schema), $1 per request, 5 asks per session per hour; a used-up day and a sixth ask are refused before any call; a refused $3/day hold releases the warehouse hold to 0; an exception mid-ask keeps both holds charged. A wrong or owner passcode builds no client; keys without the guards, with the owner ledger or with a trace id are refused; owner mode never uses them. Each Anthropic (401, 429, 404, other) and OpenAI (401, insufficient_quota, 429, other) failure fails only its panel with its fixed text, one call (two for a rate limit: one quick retry), no fallback, and the result JSON quotes no part of the key; `VisitorKeyFailed` has no cause or context and classifies as a config error.
